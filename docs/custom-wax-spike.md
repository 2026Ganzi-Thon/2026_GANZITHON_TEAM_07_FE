# 사진 커스텀 왁뿌볼

2026-11-20 · PR #18 main 병합 및 웹 배포 완료 · APK 별도 유지

최종 상태: [웹 배포 결과](custom-wax-web-release.md).

사용자 승인에 따라 아래에서 검증한 변경을 PR → main → 기존 Vercel 프로젝트 순서로 웹 배포한다. 아래의 로컬/미반영 표시는 각 검증 시점의 기록이다.

## 사용 흐름

왁뿌볼의 모양 선택 끝에 있는 `+` → 사진 선택 → 형태·크롭·안쪽 색 → 만들고 만지기.
이름 입력이나 별도의 체험 미리보기 단계는 없다. 편집 화면의 작은 사진으로 크롭만 확인한다.
저장한 사진은 같은 버튼의 보관함에서 선택·수정·삭제한다. 최대 6개.

- JPG/PNG/WebP, 파일 12MiB·원본 32MP 이하. 원본을 최대 1024px PNG로 정규화하고 겉면을 512px PNG로 생성한다.
- 일반 사진: 둥근 형태, 확대·좌우·위아래 조절.
- 투명 이미지: 사진 윤곽 선택 가능. 자동 배경 제거는 하지 않는다.
- 안쪽: 크림 화이트·연분홍·라벤더·하늘색.
- 사진이 겉 왁스가 된다. 누른 조각만 떨어져 안쪽 색이 드러나며, 전체 파괴 뒤에만 말랑하게 누르고 늘릴 수 있다. 쉬면 기존 주기에 맞춰 겉면이 다시 생긴다.
- 색이 물리적으로 섞이는 시뮬레이션은 이번 범위에 포함하지 않는다. 기존 왁뿌볼 사운드와 조작을 재사용한다.

## 저장과 기존 기능의 경계

IndexedDB `teslang-custom-wax` / `wax`에 사진과 설정만 저장한다. 업로드/API 호출 없음. 같은 origin·브라우저에서 새로고침 후 다시 선택할 수 있다. 다른 기기·포트·브라우저와 동기화되지 않으며 브라우저 데이터를 지우면 삭제된다. 마지막 선택 자체는 새로고침 시 기본 버터로 돌아가고 사진 목록은 유지된다.

WebKit의 Blob 저장 실패를 확인하여 ArrayBuffer로 저장하고 읽을 때 PNG Blob으로 복원한다. 저장 완료 전에는 편집 창을 닫거나 기존 항목을 교체하지 않는다. 저장 실패 시 초안을 유지한다. 수정은 동일 트랜잭션에서 교체하고 삭제된 object URL/이미지 캐시는 해제한다.

고정 9종의 ArtworkId 및 서버 기록의 추천 모양 허용 목록은 유지한다. 커스텀 ID는 체험용 레지스트리에만 등록하며 상담 추천·기록 API에 보내지 않는다. 삭제한 선택 항목은 버터로 돌아간다. 기존 main 및 APK 브랜치를 변경하지 않는다.

## 검증

- TypeScript + production build 통과.
- 단위 테스트 163개/20파일 통과. 새 검사는 유효하지 않은 저장 데이터, 가는/분리된 윤곽의 타격 가능 조각, 전체 파괴·복원.
- Playwright Chromium/WebKit 각 3개, 총 6개 통과: 사진 생성·수정·삭제·재조회, 동일 위치 연타, 전체 파괴 전 조작 제한/후 조작 및 복원, 투명 영역 오탭, 잘못된 파일, 편집 취소, 저장 실패 후 재시도, 6개 제한과 제한 중 수정, 슬랑이·스퀴시 전환.
- 모바일 크기 320×568, 390×844, 430×932 및 가로 844×390에서 편집창 가로 넘침과 저장 버튼 접근 확인.
- 실제 마우스 클릭/드래그와 합성 pointer 이벤트를 함께 사용. WebKit 자동화는 실제 iPhone 검증이 아니다. 새 음원 청취 테스트는 하지 않음(기존 음원 유지).
- 발견 후 수정: 기존 모양 버튼 CSS가 편집창 버튼에 상속되어 늘어나는 문제; WebKit Blob 저장 실패.

관련 코드: `src/features/toy/customWax.ts`, `customWaxImage.ts`, `useCustomWax.ts`, `CustomWaxSheet.tsx`.
검사: `src/features/toy/customWax.test.ts`, `tests/custom-wax.spec.ts`.
기존 Playwright mock 서버에서 `npx playwright test tests/custom-wax.spec.ts`로 실행 가능.

커밋·푸시·PR·병합·배포는 진행하지 않음. 로컬 확인 후 범위 결정.

## 커스텀 왁뿌볼 웹 최종 준비 확인

- 보관 안내/삭제 안내/개수 표시 제거. 편집 하단 여백과 선택 색 테두리 가림 보완.
- 가로 화면의 좁은 모양 선택 영역은 4개 버튼을 2열로 배치. 320/390/430px, 844×390, 1280×720에서 44px 이상 타격 영역 및 클릭 접근 확인.
- 단위 테스트 163개 통과. Chromium 6개 + WebKit 6개 = 총 12개 시나리오 최종 통과(커스텀 8개, 기존 홈 진입/종류 전환 4개). 각 검사 결과를 합산한 수이며 한 번의 전체 실행 결과는 아님.
- WebKit 중간 실행에서 페이지 생성 타임아웃/페이지 크래시가 발생했고 Windows PowerShell에서도 OutOfMemory가 확인됨. 이전 APK 미리보기 서버를 종료해 메모리를 확보한 후 실패 시나리오 재실행 통과. APK 소스/빌드 산출물 변경 없음.
- 최종 편집창과 가로 화면 캡처 확인. 브라우저 검사는 mock 데이터 및 자동화 환경이며 실제 휴대폰 검증이나 새 운영 상담 생성 검증으로 표시하지 않음.
- 운영 무인증 `/api/v1/auth/me`: 401 JSON 확인. API/인증 코드는 이번 변경에 포함하지 않음.
- 커밋/PR/main 병합/배포는 아직 진행하지 않음. 확인용 웹은 5193, APK 작업은 이후 별도 진행.
