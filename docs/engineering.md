# 프론트엔드 기술 구성과 작업 기준

## 말랑이 재질 업데이트 · 2026-11-18

버터 원화 교체, 하트의 전체 파괴 후 조작 흐름 통일, 제공 음원과 움직임에 반응하는 슬랑이 지속음을 반영했다. 최종 동작·코드·출처·재현 절차는 [변경 명세](design/material-refresh-2026-11-18.md)를 따른다. 최종 확인한 왁뿌볼 추출 WAV3개를 프로젝트에 포함해 일반 실행과 로컬의 소리를 통일했다. 별도 환경변수나 원본 영상은 실행에 필요하지 않다.

## D54 — 상단 정렬·제공 자산 교체 (2026-11-17)

말랑이 체험의 종류 선택·소리·메뉴를 기존 종류 선택 높이(일반 화면 top80px+safe area)에 한 줄로 배치한다. D55 보완으로 하단은 중앙의 체험 마치기만 남기고 메인의 초기화 버튼은 제거했다. 제공 PNG를 음성 채팅 아이콘/석상·MY 프로필에 연결했다. 메뉴 PNG는 형태 참고로만 보존하며, 실제 상단 메뉴는 반투명 유리 효과와 버튼 내부 아이콘·글자 묶음 중앙 정렬을 사용한다. 추천의 남은 문장 카드에는 Pretendard(라벨500/본문600)를 쓰고 메인 하단 문구/화살표 간격은5px로 줄였다. 기존 대화·음성·기록 동작은 유지한다.

## D53 — 하트 길게 누르기·왁스 벗겨짐 (2026-11-17)

하트는 꾹 누르는 동안 파열음을 이어 재생하고, 접점 주변 왁스 일부가 들려 안쪽 색상이 드러난다. 짧은 누름은 구김 중심이며, 손을 떼면 소리는 멈추고 원본으로 복원된다. 버터·구름의 전체 파괴 후 조작 규칙과 로컬 음원 범위는 유지한다.

## D52 — 버터/하트 비교 구현 (2026-11-17, 로컬 검토)

버터는 접점 한 조각 안의 작은 파편이 접혔다 떨어지며 **전체 파괴 후에만 안쪽 조작**을 허용한다. 하트는 별도 비교안으로 **누른 주변의 면이 구겨졌다가 손을 떼면 원본으로 돌아오며**, 껍질 파괴/안쪽 단계가 없다. 구름은 D51을 유지한다. 최종 공통 동작은 미확정이다. 버터·하트는 제공 녹화에서 추출한3개 효과음을 로컬에서만 사용한다. 파일은 Git 제외 artifacts에 두고 Vite 미들웨어로 제공하며 public/dist에 포함하지 않는다. 공개 재사용 조건은 미확인이다. 로그인·수면·음성은 변경하지 않았다.

[동작·로컬 음원 설정·검증](design/wax-comparison-2026-11-17.md).

## D51 — 이전 기준

### D51 — 전체 파괴 후 조작·거친 균열음 (2026-11-17, 로컬 검토)

**껍질을 모두 깨뜨린 뒤에만 안쪽을 누르고 늘릴 수 있다.** D50의 부분 파괴 중 안쪽 조작은 제거했다. 이미 깨진 곳을 다시 눌러도 다른 조각을 깨뜨리거나 부드러운 효과음을 내지 않는다. 전체 파괴 후 조작·손 떼기·대기·껍질 복원 흐름과 작은 가장자리 조각 보정은 유지한다. 파열음은 음높이가 있는 성분을 빼고 낮고 거친 균열과 촘촘한 잔파열을 겹치는 독립 합성음으로 수정했다. 참조 사이트 음원/코드는 복사하지 않았다. 로그인·수면·음성은 유지한다.

[동작·출처·검증 경계](design/wax-complete-crunch-2026-11-17.md).

## D49 — 터치 위치 파괴·음성 화면 (2026-11-17, 로컬 검토)

왁뿌볼은 누른 다각형 조각 하나만 파괴하고 이미 깨진 곳의 입력을 다른 조각으로 넘기지 않는다. 새 파괴에만 파열음을 낸다. 당시의 부분 자동 복원은 D50의 전체 파괴 후 복원으로 대체했다. 음성 패널은 하단 높이를 제한해 석상/말랑이를 노출하고 전사·답변을 같은 내용 영역에 번갈아 표시한다. 인식 시작 후20초간 전사 결과가 없는 무한 대기는 중단하지만 실제 음성 서비스 연결 문제는 미해결이다. D48의 확장 패널보다 이 기준을 우선한다. [동작·원본 확인·검증 경계](design/wax-local-voice-layout-2026-11-17.md).

## D48 — 재질 피드백·음성 입력 (2026-11-17, 로컬 검토)

`useVoice`는 SpeechRecognition 인식만 소유하고 음성 합성을 호출하지 않는다. ready=false일 때 캡처를 정리하며 미확정 글은 초안에 보존한다. 최종 이벤트 후 cycle을 갱신해 입력 검증 실패로 ready가 변하지 않아도 다시 듣는다. `MicrophoneCheck`의 getUserMedia는 인식기와 별개인 로컬 레벨 진단이며6초 측정/15초 대기 한도/늦은 스트림 정리가 있다.

## 현재 시안의 동작과 한계

전체 목록과 제품 미정 사항의 분리는 [implementation.md](implementation.md)를 따른다.

- 실제 서버 대신 MSW의 메모리 저장소(`mocks/store.ts`)가 체험 프로필·결과·인벤토리를 관리한다. 새로고침 시 초기화되며 localStorage·쿠키에 상담 내용이나 토큰을 저장하지 않는다.
- 대화는 결정적인 예시 스크립트다. 6개 감정과 추천 매핑은 fixture다. 실제 AI 분석·의학적 판단·운영 정책이 아니다.
- 완료된 대화는 고유 ID로 결과 화면에 전달한다. 결과의 자동 생성 요청은 ID 기준으로 중복을 막는다. 결과 query는 이 시안에서만 멱등 POST를 사용하며, 실제 서버 연동 시 완료 command와 GET query 계약을 맞춘다.
- 저장 성공 시 보관함·인벤토리 캐시를 갱신한다. 실패 시 draft를 보존하고 재시도한다. 원문 입력 밖의 새 관점·욕구를 만들지 않는다.
- 삭제 성공 후 상세 캐시 제거·목록 무효화를 수행한다. 실패 시 기록을 유지한다. 미존재·다른 계정 기록은 404 상태다.
- 늦게 도착한 요청이 계정 전환 후 다른 사용자 데이터에 반영되지 않도록 예시 handler에서 요청 시점 계정을 확인한다. 이것을 운영 인증 보안으로 간주하지 않는다.
- D34에 따라 세 종류 모두 처음부터 선택한다. 체험의 종류 선택과 상담의 추천 필드를 분리한다. 추천은 종류를 잠그거나 해제하지 않는다.
- Canvas 2.5D의 국소 눌림·늘리기·껍질 파괴와 제공 PNG 9개 모양을 구현했다. 실제 3D/유체 해석이 아니며 상태/체험 기록 API는 연결하지 않았다. 추천은 현재 선택 모양, 기록은 종류별 기본 그림, 그래픽 출력 실패 시에는 현재 선택 PNG를 표시한다. 슬랑이/스퀴시는 WebGL 텍스처 메시/Canvas 대체 출력, 왁뿌볼은 Canvas 껍질/내부층이며 상세 구현은 [D45](design/toy-artwork-2026-11-17.md)를 따른다.
- 위험 fixture는 도움 화면으로 전환하고 일반 상담·결과 생성을 중단한다. 연락 수단 근거는 implementation 문서에 기록한다. 실제 위험 탐지 성능은 검증하지 않았다.
- 종료 확인창은 D37에서 채택했다. D38에서 전송한 대화의 중간 보관을 추가했다. 삭제 확인은 별도로 유지한다.

## 반응형·접근성

- 앱의 데스크톱 기준 폭은 원본 프레임과 같은402px이며 휴대폰은 가용 폭을 사용한다. 바깥 장식 문구는 제거했다.
- `visualViewport` 높이와 안전 여백을 반영하고 대화 목록만 스크롤한다. 실제 휴대폰 키보드와 브라우저 UI는 실기기 검수가 추가로 필요하다.
- 한글 조합 중 Enter는 전송하지 않는다. Shift+Enter는 줄바꿈, 공백만 있는 입력은 전송하지 않는다.
- 버튼은 접근 가능한 이름과 focus-visible 표시를 갖고, dialog는 초점 이동·Escape·닫기 후 복귀를 제공한다.
- 줄인 모션 환경에서는 부유·타이핑·전환 애니메이션을 줄인다. 새로운 메시지는 이전 대화를 읽는 사용자의 스크롤을 강제하지 않고 이동 버튼을 표시한다.

## 실행과 QA

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npx playwright install chromium webkit
npm run test:e2e
```

기본 주소는 `http://127.0.0.1:5173`이다. MSW의 Service Worker는 localhost 또는 HTTPS에서 동작한다. 휴대폰 실기기에서는 localhost가 개발 PC를 가리키지 않으므로 HTTPS 미리보기 배포 등 접속 구성을 별도로 준비한다.

현재 빌드도 화면 검토용 예시 모드다. `VITE_API_MODE=mock`이 기본이며 다른 모드는 아직 지원하지 않는다. 앱 공개 운영 전 실제 API 어댑터·인증·데이터 정책을 구현하고 예시 handler와 안내의 배포 방식을 결정해야 한다. SPA 배포 시 `/chat` 직접 접근을 위한 index.html fallback도 필요하다.

패키지 설치·코드 작성과 검증은 승인된 범위에 포함한다. 외부 배포·새 서비스 계정 연결·Git 커밋과 푸시는 별도 요청이 있을 때 진행한다.

## 선택적 QA 실행 환경

브라우저·추적 파일을 별도 디스크에 두는 경우 `scripts/qa.ps1 -RuntimeRoot <로컬 도구 폴더>`를 사용한다. 해당 프로세스의 브라우저/임시/추적 경로만 바꾸며 종료 후 복원한다. 특정 드라이브는 필수 조건이 아니다.

빌드 검사는 `npm run build:mock` 후 `QA_SERVER_MODE=preview` 환경변수로 Playwright를 실행한다. preview는 5183 포트, mock 개발 검사는 5185 포트(`npm run dev:mock`)를 쓴다. 개발자가 띄운 `npm run dev`(5173, real 기본)를 재사용하지 않게 포트를 분리했다. 실행 방법과 실제 검사 결과는 [QA 기록](qa.md)을 따른다.

## 요청 복구와 완료 payload — 2026-11-14 보완

- `api.ts`는 fetch 시작부터 JSON 본문 수신까지 30초 제한 시간을 적용한다. 타임아웃은 408, 연결 실패는 0, 성공 응답의 잘못된 JSON은 502로 구분하는 프론트 `ApiError`다. 실제 서버가 그 코드를 응답했다는 의미는 아니다. HTTP 오류는 서버 status를 유지한다.
- Query/Mutation의 `networkMode: always`로 오프라인에서 요청이 무기한 paused 상태로 남지 않게 하고 fetch 오류 UI로 연결한다. 네트워크/HTTP 실패는 자동 재시도하지 않는다. 잘못된 대화 응답만 아래 계약 검증 기준으로 1회 재요청한다. 이 설정이 오프라인 저장이나 동기화를 제공하지 않는다.
- Chat은 AbortController로 화면 이탈 시 응답 대기를 해제한다. 저장/삭제 요청은 화면 이탈만으로 취소하지 않는다. 타임아웃 후 실제 서버가 쓰기를 완료했을 가능성은 어댑터에서 멱등 키·재조회로 해결해야 한다.
- `ResultDraft.messages`에는 표시된 대화의 역할·순서·내용이 모두 포함된다. 재시도 시 같은 snapshot을 사용한다. 이 타입은 `/__preview__/` 전용이며 실서버 DTO가 아니다. 예시 handler는 slots 발췌를 만들고 messages는 현재 세션 메모리에만 복사한다. 실제 AI 요약·영속 저장은 하지 않는다.
- `Modal.dismissible`은 삭제/종류 변경의 처리 중 상태에 연결한다. native dialog의 Escape 기본 동작을 항상 취소하고 React 상태로만 닫아 DOM과 상태가 어긋나지 않게 한다.
- 포인터 캡처는 소유 pointerId의 종료만 처리한다. 창 초점 이탈·탭 숨김·포인터 취소·컨트롤 초점 이탈에서 복원한다.

## 응답 계약 방어 — D32

`contracts.ts`는 프로필, 인벤토리, 기록, 대화 응답을 `unknown`에서 검사한다. null과 0, 슬롯의 문자열, 유효한 enum, 선택된 종류의 해금 포함 여부, 기록 ID 중복 등을 확인한다. 대화는 허용 필드만 반환해 사용자 감정·점수·메시지 배열이 서버의 추가 필드로 덮어써지지 않게 한다.

`ResponseShapeError`는 프론트에서 생성한 502 오류다. 대화만 이 오류에서 동일 requestId/payload로 최대 한 번 더 요청한다. HTTP/연결 실패·저장·삭제는 자동 반복하지 않는다. 취소 후 추가 재요청도 하지 않는다. 현재 물음표 개수와 단계 enum 검사는 의미상 질문 개수나 서버 단계 전이·실제 LLM `question_stage` 전체를 검증하지 않으므로 AC10은 부분 구현이다. 실제 어댑터 연결 시 멱등성과 재생성 요청 방식도 서버 계약에 맞춘다.

D34(2026-11-15): D34 적용 기준으로 세 종류를 처음부터 개방했다. 메인(비로그인 포함)·체험·결과에서 잠금 UI와 추천 해금 조건을 제거했다. 기존 추천 기록은 유지한다. 실제 서버의 잠금 정책은 아직 수정하지 않았으며 연동 시 맞춰야 한다.

## D38 중간 저장·가리기·추천 선택 계약

- `ResultDraft.partial=true`는 미완료 Context와 전송된 Message 배열을 스냅샷으로 POST한다. 빈 대화/SAFETY는 거부하며 같은 id 재요청은 기존 기록을 반환한다. `recommended=null`을 허용하는 것은 partial 기록뿐이다.
- `DiaryRecord.hidden`은 표시 상태다. `PATCH /__preview__/records/:id { hidden: boolean }` 성공 후 상세 캐시 갱신/목록 무효화. 일반 보관함은 필터 후 모든 집계를 수행한다. 관리 화면은 전체 기록을 사용하고 숨긴 요약은 표시하지 않는다. 프론트 가리기는 암호 잠금이 아니다.
- 실제 BE의 abort/complete 상태와 partial 저장·hidden API는 지원 여부/DTO/권한/보관정책 확인 후 어댑터에서 맞춘다. 현재 서버 구현 완료로 전달하지 않는다.
- 결과의 selected는 지역 상태이고 저장된 recommended는 불변이다. 후보 클릭은 mutation하지 않으며 CTA 이후 기존 말랑이 선택 API를 따른다.
- 기본 mock 단계는 OPEN→EMOTIONS→PRE→THOUGHT→ACTION→POST→DONE. 서버 단계 enum은 축소하지 않는다.

## 실제 API 모드·인증 — #13 (2026-11-18)

- 모드: `src/lib/apiMode.ts`. 기본은 real이고(2026-11-19), Vite `--mode mock`(`dev:mock`/`build:mock`) 또는 `VITE_API_MODE=mock`이면 mock이다. mock은 전부 MSW, real은 `/api/v1/auth`만 백엔드이고 나머지 `/__preview__`는 MSW가 계속 응답한다. real에서는 로그인한 계정을 `/__preview__/bind`로 예시 저장소에 연결해 계정별로 나눈다.
- 백엔드 응답 `{ success, data, error }`는 `contracts.ts`의 `decodeEnvelope`에서 풀고, 실패는 `ApiError(status, code, details)`로 바꾼다. 화면은 `code`(예: `INVALID_CREDENTIALS`, `EMAIL_ALREADY_REGISTERED`)로 문구를 고른다.
- 로그아웃(PR #14 리뷰): 진행 중인 토큰 갱신이 끝날 때까지 기다리고, 요청 본문은 보낼 때 읽는다(`body` 함수). 그래서 401 → 갱신 → 재전송에서도 최신 Refresh 토큰을 폐기한다. 로그아웃 뒤 끝난 갱신은 `authSession.generation()`이 달라 저장하지 않는다.
- 토큰: `authSession.ts`(Access 메모리, Refresh `sessionStorage`). 저장 정책을 바꿀 때는 이 파일만 수정한다. refresh 거절 시 `expired` 이벤트로 프로필 외 캐시를 지우고 프로필을 null로 만든다. 진행 중인 프로필 조회를 지우면 화면이 대기 상태에 멈추므로 프로필 쿼리는 지우지 않는다.
- 로그인 화면: `features/account/Login.tsx`(시안 151:11030)와 `OAuthCallback.tsx`(`/oauth/callback/:provider`). 콜백은 독립 화면이 아니라 처리 경로다. 일회용 코드는 ref로 한 번만 교환해서 StrictMode 재실행에서도 중복 교환하지 않는다. Safari는 클릭한 버튼에 초점을 주지 않으므로, 시트를 여는 버튼에서 직접 `focus()`를 호출해 시트를 닫은 뒤 초점이 돌아오게 했다.
- 테스트: `npm run test:e2e`는 real 전용 개발 서버(5184)와 가짜 인증 서버(`tests/support/fake-auth-backend.mjs`, 8099)도 띄운다. `tests/auth.spec.ts`는 real-chromium/real-webkit 프로젝트에서만 실행된다. 가짜 서버는 백엔드 문서의 응답 형태만 흉내 낸 것으로 실제 백엔드 검증이 아니다.

## D39 연동 시 주의

- `PreviewRequest.continueOpening`은 프론트 체험의 명시적 계속하기 의도다. 운영 API 계약에 추가됐다는 뜻이 아니다. 운영 단계 판단은 서버와 합의하고 예시 `previewReply`를 교체한다. 임시 단계 진행은 의미 분석/상담 정확도 검증 대상이 아니다.
- Web Speech 인식은 생성자 존재만으로 사용 가능하다고 판단할 수 없다. 사이드패널에서 시작 이벤트 뒤 `network` 실패를 재현했다. 지원 브라우저에서도 공급자 연결이 별도로 필요하다. 시작 10초 제한, 빈 종료 1회 재시작, 오류 시 초안 보존과 시간 정지/수동 재시도를 구현했다.
- 공통 브라우저 지원이 필요하면 STT 공급자와 서버 중계/인증/스트리밍 계약이 필요하다. 현재 구현에 서버 STT나 API 키가 추가되지는 않았다. 클라이언트에 비밀키를 넣거나 가상 전사로 성공을 꾸미지 않는다.
- 기록 상세의 `view=conversation`은 UI 상태다. DB/API 경로를 늘리지 않는다. 카드에 실제 수집한 슬롯만 렌더링하고 추천을 실제 사용 이력으로 바꾸지 않는다.


## D46 렌더링·오디오 수명

표면 경사 명암과 국소 메시를 함께 사용하며 GPU가 없으면 같은 높이 식을96×96 조명 텍스처로 만들어 Canvas에 알파 합성한다. 출력이 정지하면 RAF를 멈추고 물성/껍질 복원 시작에만 타이머로 다시 깨운다. 활성 포인터 동안 껍질 재생은 멈춘다. 오디오는 기본 ON이지만 첫 조작 전 컨텍스트를 만들지 않는다. 첫 입력은 오디오 시간축에 바로 예약하고 준비되지 않은 파일은 기존 짧은 합성 효과로 대체한다. 음소거/이탈 시 활성화 대기 중인 소스도 즉시 취소한다. 비동기 완료 콜백에서 예전 입력을 재호출하지 않는다.
