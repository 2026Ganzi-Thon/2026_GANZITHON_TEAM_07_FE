## AI 감정 대화에 필요한 사항 (F-02)

### 1. 응답 형식 (문서와 맞추기)

`.scratch/emotional-dialogue/05`의 `userMessage` / `extractedData` / `transitionReady` 대신, 테스트를 마친 프롬프트 응답 형식으로 맞추기

| 프롬프트 응답 키 | 의미 |
|---|---|
| reply | 사용자에게 보여 줄 말 (= userMessage) |
| stage_done | A: 현재 단계 완료 / B: 방금 물은 것에 답했는지 (= transitionReady) |
| thought, need, summary | 추출 데이터 (= extractedData) |
| action_options | 행동 선택지 |
| end_requested | 사용자 종료 요청 |
| risk_flag | 위험 신호 (2차 확인) |

### 2. 대화 진행 방식

- 단계(`current_step`)는 서버가 관리하고, AI 응답의 `stage_done`을 보고 넘긴다.
- 단계를 넘기는 기준은 모델 확정 후 테스트로 정한다.
  - A. AI가 단계 완료를 판단 (`stage_done`) — 자연스러움, 모델 성능에 의존
  - B. 서버가 매 턴 "다음에 물을 것"을 지정하고 AI는 답 여부만 판단 — 안정적, 순서 고정
- B로 가면 `session_state`에 진행 상태를 추가한다.

```json
"flow": { "asked": "REFRAME_ALT", "nextAsk": "NEED", "canReask": false }
```

### 3. API

- 감정·강도 입력 시점: 세션 생성 때가 아니라 상황을 들은 뒤 받기
  - `POST /sessions`: 첫 메시지만
  - `POST /sessions/{id}/emotions` (신규): `primaryEmotion`, `secondaryEmotion`, `preIntensity`
- messages 응답 필드 추가: `inputRequired`(`EMOTION` / `POST_INTENSITY`), `actionOptions`
- 대화 중 종료 요청: `end_requested`면 `inputRequired: "POST_INTENSITY"`로 응답해 정리까지 진행
- 마음 기록함 상세(`GET /records/{id}`) 응답에 4번에서 추가하는 감정 기록 필드 포함

### 4. DB

- `counseling_results`에 감정 기록 칸 추가 (마음 기록함 11-1: 기존 생각과 새로운 관점, 대처 방법 및 행동)
  - `secondary_emotion`, `trigger_factor`, `initial_thought`, `alternative_thought`, `underlying_need`, `coping_strategy`, `action_plan`
- `counseling_messages`에 AI 응답 JSON 원문 컬럼 `ai_payload` (JSON, nullable)

### 5. 대화 기록·타임아웃 (문서 04·07과 다른 점)

- 대화 기록: 일반 턴은 최근 6~8턴이어도 되지만, 정리 호출은 대화 전체를 보내야 함. 상담 1회가 15턴 안팎이라 전체를 보내도 부담이 적음
- AI 발화는 `message_content`(글)가 아니라 `ai_payload`(JSON 원문)로 넣어야 형식이 유지됨
- 정리 호출은 일반 턴보다 오래 걸려서 타임아웃을 따로 길게

### 6. 확인 필요

- 말랑이 추천 매핑(06번 문서: 불안·우울→슬랑이, 속상함·슬픔→스퀴시, 분노·스트레스→왁뿌볼)이 기획 확정안인지
- 말랑이 추천 사유를 LLM이 생성할지 (생성하면 프롬프트 응답에 칸 추가)
- `counseling_results.summary`(1~2줄)를 정리 단계 화면 문장과 따로 받을지
- 부가 감정 필수 여부
- 2차 위험 확인을 별도 분류기 대신 같은 응답의 `risk_flag`로 하는 것

## 11월 11일 01시 2분 수정사항

### 1. 테스트 기준

- 모델: Claude Haiku 5.5 (`claude-haiku-5-5`), JSON 스키마 강제(structured outputs)
- 진행 방식: A (AI가 `stage_done`으로 단계 완료 판단) + 아래 서버 처리 보강
- 프롬프트: `prompts/emotion-conversation/system.v4.md`, `fewshot.v4.md`
- 자동 시뮬레이션 10개 시나리오(기본, 첫 메시지에 다 말함, 모르겠어/없어, 쉬고 싶음, 막연한 다짐, 중간 종료, 위험 3종, 부당한 일) 기대대로 동작

### 2. 응답 형식 추가

| 키 | 의미 |
|---|---|
| question_stage | 이번 응답의 질문이 어느 단계 질문인지 (질문 없으면 null) |

### 3. 서버가 처리할 부분 (AI 대화 한 턴 기준)

AI는 현재 단계에서 할 말과 판단만 한다. 나머지는 서버가 처리한다.

#### ① 호출 전: 프롬프트 조립

- 현재 단계(`stage`)·다음 단계(`next_stage`)는 서버가 관리하고 매 호출에 넣는다
- 프롬프트 칸 채우기: 고른 감정, 감정 강도, `thought`, `need`
- 대화 기록
  - AI 발화는 `message_content`(글)가 아니라 `ai_payload`(JSON 원문)로 넣는다
  - 정리(`SUMMARIZE`) 호출은 대화 전체를 보낸다
- 사용자 메시지 끝에 서버 지시 한 줄(현재 단계 / 할 일 / 완료 기준)을 붙인다. 기록에는 사용자 원문만 저장
- 위험 신호 1차 검사(키워드)는 AI 호출 전에 한다

#### ② 호출 직전: "모르겠어" / "없어" 판정

- 답 전체가 그 말뿐일 때만 판정 ("딱히 없어", "그래도 잘 모르겠어"). "하루밖에 없었어"처럼 내용 있는 답은 판정하지 않음
- 같은 단계에서 첫 번째: "다시 묻기" 지시를 붙여 호출
  - ACTION에서 직전 질문이 작은 행동을 물었으면 "행동 선택지 제시" 지시를 붙임
- 두 번째: `stage_done`을 true로 강제
- NEED·RESOURCE의 "없어"는 첫 번째여도 바로 완료

#### ③ 호출 후: 검증과 재요청 (1회)

- JSON 형식·필수 키 오류 → 재요청
- 물음표 2개 이상 → 재요청
- SUMMARIZE에서 질문 → 재요청
- `stage_done: false`인데 `question_stage`가 현재 단계가 아님 → 재요청 (예외: ACTION에서 `action_options`를 준 턴은 통과)
- 재요청도 실패하면 고정 문구로 응답

#### ④ 응답 처리

- `risk_flag: true` → 상담 중단, 상담 연결 화면
- `end_requested: true` → 사후 감정 강도 입력(`inputRequired: "POST_INTENSITY"`) 후 정리로
- `thought`, `need`가 오면 세션 상태에 저장
- `action_options`가 있으면 화면에 선택지로 표시
- `stage_done: true`면 다음 단계로
  - 다음이 NAME → 감정 선택 화면 (`inputRequired: "EMOTION"`)
  - `thought`가 이미 있으면 CLARIFY, `need`가 이미 있으면 NEED를 건너뜀
  - 질문하는 단계(CLARIFY~ACTION)로 넘어가면 방금 응답의 질문은 버리고, 같은 사용자 메시지로 새 단계를 한 번 더 호출해 첫 질문을 받아온다. 이 재호출은 `stage_done`을 false로 고정
  - 다음이 SUMMARIZE → 사후 감정 강도 입력 후 정리 호출

#### ⑤ 정리 저장

- `summary.emotions`는 화면에서 고른 대표·부가 감정으로 덮어씀
- `summary` 각 칸을 `counseling_results`에 저장 (4. DB 참고)
- 감정 강도(전·후), 말랑이 추천 매핑은 서버 처리

#### ⑥ 기타

- 타임아웃은 일반 턴과 정리 호출을 따로, 정리 호출을 더 길게
- 단계 전환 턴은 호출이 2번이라 로딩 표시 필요
- 상담 1회 AI 호출 14~18번, 일반 턴 1.5~2.5초, 단계 전환 턴 3~7초

### 4. 프롬프트 수정 (기획안 원문이 아닌 구현 보강 규칙)

- CLARIFY: 생각이 나오면 바로 완료, 생각의 이유는 REFRAME에서만 물음
- REFRAME: 근거 질문에 생각 문장을 넣어 묻고, 근거를 이미 말했으면 건너뜀. 다른 해석은 "그 일이 일어난 데 다른 이유나 사정"을 사건을 넣어 구체적으로 물음
- ACTION: 바라는 상황·결과("하나라도 끝내고 싶어")는 행동으로 보지 않고 작은 행동을 다시 물음. 막연한 다짐도 동일
- 쉬고 싶다고 하면 `action`에 "오늘은 쉬기"로 기록

### 5. 남은 결정

- OPEN 완료 기준: 짧은 첫 메시지면 한 번 더 물을지, 사건만 나오면 넘어갈지
- 감정 기록 문장 형식: `thought`·`need`를 사용자 원문 그대로 둘지, 전부 서술형으로 맞출지
