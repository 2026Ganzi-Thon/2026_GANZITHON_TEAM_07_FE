## 두 가지 시작 방식

| 시작 방식 | 기획안의 의도와 연결 |
|---|---|
| 말랑이 먼저 | 메인에서 말랑이를 만지며 감정을 환기한다. 필요하면 감정 기록·대화로 들어간다. |
| 감정 기록 먼저 | 상황을 말하고 감정을 고른 뒤 AI와 생각·욕구·대처·행동을 정리한다. 결과와 추천을 보고 말랑이 체험으로 이어진다. |
| 마음 기록함 | 날짜별 기록을 찾아 상세 내용을 확인한다. |

AI 상담을 거쳐야만 말랑이를 만질 수 있는 구조는 기획안의 두 진입 경로와 맞지 않는다. [N02 §8, §12~13]

## AI 문서에 적힌 정상 진행

`첫 메시지 → OPEN 상황 탐색 → NAME 감정·사전 강도 입력 → CLARIFY 생각 → REFRAME 다른 관점 → NEED 욕구 → RESOURCE 대처 자원 → ACTION 작은 행동 → 사후 강도 입력 → SUMMARIZE 정리·저장 → 추천 및 체험`

이는 N11의 단계와 N13의 서버 처리를 함께 읽은 순서다. 매번 모든 단계를 질문한다는 뜻은 아니다. 이미 확보한 생각·욕구는 N13에서 해당 단계를 건너뛴다. 단계별 완료 기준은 [대화정책](대화정책.md)에 따로 정리했다.

## 종료·위험 분기

- 사용자 종료 요청: N13은 `POST_INTENSITY` 입력을 요구하고 정리로 연결한다.
- 위험 감지: 일반 대화를 중단하고 상담 연결 화면으로 보낸다. 일반 결과 흐름과 다르다.
- 구체적인 이탈·재접속·뒤로가기·확인창 정책은 이 노션 자료에서 확정하지 않는다.
- 감정 선택 전 중단, 사후 점수 없이 결과 제공 등의 세부 예외는 확인한 원문만으로 확정하지 않는다.

## 기록 저장 시점은 문서 간 차이가 있음

N02의 서비스 루프에는 체험 후 기록이 놓여 있으나, N13에는 정리 결과를 DB에 저장하는 처리가 명시되어 있다. 두 표현을 합쳐 ‘체험해야만 저장된다’ 또는 ‘원래 모든 문서가 자동 저장으로 통일되어 있다’고 단정하지 않는다.

N18의 초기 회의록은 ‘재질 터치 → 감정 선택 → 행동 → 오브젝트 기록’으로 표현한다. 초기 아이디어 기록이며 이후 대화 단계 정의와 동일한 상세 플로우는 아니다.
