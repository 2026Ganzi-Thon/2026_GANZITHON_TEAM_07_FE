## 감정은 어떻게 입력하는가

N02와 N11은 사용자가 화면에서 감정을 고르는 흐름이다. N13은 상황 탐색 후 감정·강도를 받는 `/emotions`와 `inputRequired: EMOTION`을 제안하고, 정리 결과의 감정을 사용자 선택값으로 덮어쓰도록 적고 있다. AI가 문맥을 이해하는 것과 선택값을 임의로 바꾸는 것은 구분된다.

| 항목 | 노션에 적힌 내용 | 이 자료만으로 확정할 수 없는 부분 |
|---|---|---|
| 대표 감정 | 대표 감정 1개를 먼저 선택 | 전체 선택 목록·식별 코드 |
| 부가 감정 | N02·N11의 대표 1개+부가 1개, N09의 최대 2개 | 필수 여부: N13 확인 필요 항목 |
| 목록 밖 감정 | 예시에 다양한 감정 단어가 등장 | 자유 입력 허용 여부, 검증·추천 실패 처리 |
| 분석 결과 감정 | N13에서 선택값으로 덮어쓰기 | 사용자가 뒤로 돌아가 변경할 때의 처리 |

## 추천 표에 등장하는 6개 감정

| 감정 | N02 추천 대상 |
|---|---|
| 불안, 우울 | 슬랑이 |
| 속상함, 슬픔 | 스퀴시 |
| 분노, 스트레스 | 왁뿌볼 |

이 표는 **추천 매핑**이며 전체 선택 가능 감정 목록이라고 명시되어 있지 않다. N09에는 서운함 예시, N12에는 허탈함·자괴감 등의 선택 감정 예시가 있다. 따라서 여섯 감정을 그대로 허용 목록으로 단정할 수 없다. N13도 추천 매핑의 확정 여부와 추천 사유를 LLM이 만들지 여부를 확인 필요로 남겼다.

대표·부가 감정의 추천 대상이 다를 때 무엇을 우선할지, 표에 없는 감정의 대체 추천, 두 감정의 조합 규칙은 확인한 노션에서 확정되지 않는다.

## 감정 강도

N02·N09·N11은 상담 전후 0~10점을 사용자가 직접 입력하고 AI가 추측하지 않는 원칙을 제시한다. N13은 사전 입력을 감정 입력 API에 포함하고, 사후 입력 뒤 정리하도록 한다.

- 대표 감정만 평가하는지 두 감정 전체를 평가하는지 구체적인 기준은 명확하지 않다.
- 시작 점수, 미선택 UI, 양끝 안내 문구, 점수 건너뛰기는 노션의 확정 규칙으로 적지 않는다.
- N03에는 1~10 예시 및 P2 표기가 있어 N02의 0~10·필수 흐름과 차이가 있다.
- N08의 해결중심 척도는 ‘바라는 상태에 얼마나 가까운가’를 묻는 설명이다. 감정 강도의 높고 낮음과 자동으로 같은 의미로 쓰지 않는다.

## 추천 이후 선택 범위

N02는 추천과 말랑이 종류 변경을 다룬다. 그러나 잠금·해금의 상세 조건이나 처음부터 모든 종류를 고를 수 있는지는 이 문서들만으로 확정하지 않는다. GitHub의 규칙을 이번 노션 보관본에 옮겨 넣지 않았다.
