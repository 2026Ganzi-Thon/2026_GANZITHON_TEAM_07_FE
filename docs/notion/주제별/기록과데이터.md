## 기록에 포함되는 내용

N02는 날짜별 감정 기록에서 상황·감정, 전후 감정 강도, 기존 생각과 새로운 관점, 대처 방법·실천 행동, 추천 등을 확인하는 방향을 제시한다. N09는 이를 데이터 구조 제안으로 확장하고, N13은 DB에 추가할 구체적인 필드를 적고 있다.

| 내용 | 문서의 필드·표현 | 주의점 |
|---|---|---|
| 상황·계기 | situation, trigger_factor | 상황 요약과 촉발 요인을 구분하는 문서 표현을 보존 |
| 대표·부가 감정 | primaryEmotion, secondaryEmotion / secondary_emotion | API와 DB 이름을 혼용한 통일 스키마로 만들지 않음 |
| 기존 생각 | thought / initial_thought | 사용자 표현 그대로인지 서술형인지 N13에서 미정 |
| 다른 관점 | alternative_thought | 사용자가 말하지 않았으면 AI가 새로 만들지 않음 |
| 욕구 | need / underlying_need | 이미 확인된 욕구는 중복 질문하지 않는 보강 규칙 |
| 대처 자원 | coping / coping_strategy | 대처가 없거나 미확보된 경우를 구분할 세부 스키마는 추가 확인 필요 |
| 작은 행동 | action / action_plan | 원하는 결과와 구체 행동을 구분 |
| 강도 | 상담 전·후 점수 | 사용자 직접 입력, AI 추정 금지 |
| 짧은 요약 | counseling_results.summary | 별도 1~2줄을 받을지는 N13 확인 필요 |
| AI 원본 응답 | counseling_messages.ai_payload | JSON, nullable. 다음 호출의 AI 기록에도 JSON 원문 사용 |
| 위험 여부 | risk_flag | 별도 위험 기록 처리 원칙 적용 |

표는 문서에 등장한 표현을 대응시킨 것으로, 완성된 DB 스키마나 API 계약이 아니다. 타입·길이·NULL·외래키 등 명세가 없는 곳을 임의로 채우지 않았다.

## 저장 시점과 내용 검증

N13은 정리 호출에 전체 대화 이력을 보내고, `summary.emotions`를 선택값으로 덮어쓴 뒤 결과 각 칸을 저장한다. 전후 점수와 추천 매핑은 서버가 처리한다. N11은 실제 대화에서 확인되지 않은 내용을 만들어 채우지 않도록 한다.

N02 루프의 체험 후 기록 표현과 N13의 정리 저장 시점에는 해석 차이가 있다. 이번 자료에서 한쪽으로 몰래 통일하지 않는다.

## 조회·삭제·누적 분석

- N03: 기록 달력, 날짜 선택과 상세 조회, 개별 삭제, 숨김·복구 관련 행이 있으며 중요도가 서로 다르다.
- 사용자별 데이터 분리 및 삭제한 기록의 분석 제외 항목이 있다.
- N02·N09: 위험 기록은 일반 감정 패턴 분석에서 제외하고, 사용자가 기록을 지우면 함께 지우는 방향이다.
- 삭제가 상담 원문·AI 원본 JSON까지 어느 범위에 전파되는지는 확인한 문서에서 완전한 계약으로 제시되지 않는다.
- 월별 통계·누적 패턴·개인화는 N02의 후순위와 N03 일부 P0가 일치하지 않는다.

## 추가사항의 제안 상태

N09의 `thought_pattern`은 사용자에게 보여주는 진단 라벨이 아니라 내부용 제안이다. ‘원하는 결과’를 Need·Action과 별도로 둘지도 논의 항목이다. 제안된 필드를 이미 확정·구현된 필드처럼 표기하지 않는다.
