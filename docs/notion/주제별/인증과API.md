## 확인 범위

승인 범위의 **N14 API 명세서 페이지는 본문이 비어 있었다.** 따라서 이 문서는 N03 기능 명세서의 인증 요구와 N13의 API 변경안을 모은 것이다. 백엔드 저장소의 문서나 실제 구현을 확인했다는 의미가 아니다.

## 명세서에 적힌 인증 기능

| 묶음 | 적힌 내용 | 상태를 읽는 방법 |
|---|---|---|
| 로그인·가입 | 이메일, 카카오, Apple 관련 항목 | 이메일 P1, 카카오·Apple P2 등 행별 중요도 존재. 최종 채택 방식과 같지는 않음 |
| 이메일 인증 | 6자리 인증번호, 유효시간 5분, 재전송·오류 안내 | 재전송 간격 등 미정인 값 존재 |
| 약관 | 서비스·개인정보 필수 동의, 선택 동의 | 문구·처리 계약까지 완성된 것은 아님 |
| 계정 정보 | 이름·비밀번호·사용자 ID 및 검증 | 실제 API 필드 타입은 제공되지 않음 |
| 계정 관리 | 비밀번호 재설정·변경, 탈퇴, 로그아웃·토큰 제거 등 | P3 또는 확인 사항이 있는 항목을 모두 필수로 합치지 않음 |

각 행의 정확한 설명과 비고는 [상세기능표](상세기능표.md)의 회원가입·로그인·계정 관련 구간에 그대로 보존했다. 로그인 요구 시점, 선택할 공급자, 인증 API 주소, 토큰 전달 방식은 이 정리에서 새로 결정하지 않는다.

## N13의 상담 API 변경안

| 요청·응답 | 원문 설명 |
|---|---|
| `POST /sessions` | 세션 생성 시 첫 메시지만 받기. 감정·강도는 상황 탐색 이후 |
| `POST /sessions/{id}/emotions` | 신규 제안: `primaryEmotion`, `secondaryEmotion`, `preIntensity` |
| messages 응답 | `inputRequired`에 `EMOTION` 또는 `POST_INTENSITY`, `actionOptions` 추가 |
| `GET /records/{id}` | 새 감정 기록 필드를 상세 응답에 포함 |

여기 없는 HTTP 메서드·오류 코드·인증 헤더·요청 필수값·실제 배포 주소는 추정하지 않는다. N13의 API·DB 변경 요청은 구현 완료 확인 자료가 아니다.

## 프론트가 읽을 수 있는 상태 신호

N13은 `EMOTION`이면 감정 선택 화면, `POST_INTENSITY`이면 사후 점수 입력, `actionOptions`가 있으면 행동 선택지를 표시하도록 설명한다. 단계 전환 시 재호출이 생겨 로딩 표시가 필요하다고 적는다. 정리와 일반 턴의 타임아웃도 다르게 두는 방향이지만 확정된 UI 문구와 시간 제한은 없다.
