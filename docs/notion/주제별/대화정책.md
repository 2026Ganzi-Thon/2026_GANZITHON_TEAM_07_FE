## 운영 원칙

N11은 서버가 현재 단계와 다음 단계를 관리하고, AI가 `stage_done`으로 완료 여부를 판단하도록 한다. N13의 11월 11일 수정사항은 이를 A 방식과 서버 보강 규칙으로 적고 있다. 답변은 일반적으로 짧은 공감과 질문 하나로 구성하며, 사용자에게 정답을 강요하거나 같은 내용을 반복해서 묻지 않는다. 정리 단계는 질문 없이 정리한다.

질문 예시는 고정 멘트 목록이 아니다. N12는 상황과 응답을 설명하는 few-shot 예시다. 실제 사용자 발화에 맞춰 질문을 만들되, 단계와 완료 기준을 지키게 하는 구조다.

## 단계별 기준 — system.v4

| 단계 | 확보하려는 내용 | 완료·건너뛰기 기준 |
|---|---|---|
| OPEN | 감정이 생긴 구체적인 사건·상황 | 구체적인 사건이 나오면 완료. ‘혼났어’만으로 무엇이 있었는지 불분명하면 추가 질문. 다만 N13에는 이 기준을 다시 결정할 항목으로 남겼다. |
| NAME | 사용자가 고른 대표·부가 감정과 사전 강도 | 화면에서 직접 선택·입력. 최종 전체 목록과 부가 감정 필수 여부는 문서만으로 확정되지 않는다. |
| CLARIFY | 그때 떠오른 생각 | 생각이 나오면 완료. 이유·근거는 REFRAME에서 묻는다. N13은 생각이 이미 저장돼 있으면 이 단계를 건너뛴다. |
| REFRAME | 생각의 근거와 다른 해석 가능성 | 생각 문장을 넣어 근거를 묻고, 근거를 이미 말했다면 반복하지 않는다. 사건의 다른 이유·사정을 탐색한다. 다른 관점 하나 또는 다르게 생각하기 어렵다는 의사를 완료로 인정한다. |
| NEED | 감정 아래의 바람·욕구 | 감정이 컸던 때 무엇을 바랐는지 확인. ‘없어’도 완료. 이미 욕구가 확보됐으면 N13은 건너뛴다. |
| RESOURCE | 도움이 된 대처·예외·자원 | 해봤던 대처나 덜 힘들었던 순간을 확인. 없다는 응답도 완료로 인정. |
| ACTION | 사용자가 할 수 있는 작은 행동 | 바라는 결과나 막연한 다짐은 구체 행동과 구분한다. 행동을 떠올리기 어려우면 선택지 제공. 쉬고 싶다는 뜻이면 ‘오늘은 쉬기’로 기록하는 보강 규칙이 있다. |
| SUMMARIZE | 실제 대화 내용의 항목별 정리 | 질문하지 않음. 말하지 않은 관점·대처·행동을 만들어 넣지 않음. 감정은 선택값으로 서버가 덮어씀. 사후 강도 입력 뒤 호출. |

## ‘모르겠어’와 ‘없어’ — N13 서버 규칙

답 전체가 모름·없음 의미일 때만 적용한다. ‘하루밖에 없었어’처럼 내용이 있는 답은 단순 모름·없음으로 처리하지 않는다.

- 같은 단계 첫 번째: 다시 묻기 지시. ACTION에서 직전 질문이 작은 행동이었다면 선택지 제시 지시.
- 두 번째: `stage_done`을 true로 강제한다.
- NEED·RESOURCE의 ‘없어’: 첫 응답에서도 완료한다.
- 중간에 다른 답이 들어왔을 때 횟수를 누적할지 초기화할지는 원문이 구체적으로 정하지 않는다.

## 종료와 질문 생성 검증

N13은 위험 신호를 일반 진행보다 먼저 처리하며, 종료 의사는 사후 강도 입력과 정리로 연결한다. JSON·필수 키 오류, 물음표 2개 이상, 정리 단계에서 질문, 현재 단계와 맞지 않는 `question_stage` 등을 검증하고 1회 재요청한다. 재요청 실패 시 고정 문구를 사용하지만 그 문구 자체는 원문에 확정되어 있지 않다.

단계가 바뀔 때 N13은 이전 응답의 질문을 버리고 같은 사용자 메시지로 새 단계의 첫 질문을 재호출한다. 재호출에서는 `stage_done`을 false로 고정한다. N11의 ‘완료 답변에 다음 질문 포함’ 설명과 구분해서 봐야 한다.

## 원문 예시를 찾는 위치

N12에는 과제 상황을 따라가는 대화, 첫 메시지에서 생각을 이미 말한 경우, 종료 요청, 프롬프트·단계 변경 요구, 위험 상황 등 21개 예시 제목이 있다. 원래 JSON 예시를 [AI프롬프트](AI프롬프트.md)에서 검색하거나 위의 N12 보관본을 열면 된다. 대화 예시를 새로 만들어 원문 사례처럼 추가하지 않았다.
