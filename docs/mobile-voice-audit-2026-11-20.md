# 모바일 안전 여백·음성 최종 점검 (2026-11-20)

> 후속 적용: 아래 ‘아직 미반영’은 이 점검 당시 상태다. 이후 사용자 승인으로 회원가입/메인/수면 손잡이/가로 로그인 및 음성 대기 문구를 보완했고, 음성 자동 전송도 확인 후 직접 전송으로 변경했다. 현재 구현과 재검증 결과는 [최신 기록](manual-voice-and-mobile-2026-11-20.md)을 따른다.

## 이번 적용

- 음성 안내 ⓘ를 우상단으로 이동했다. 아이콘 18px, 터치 영역 44px, 오른쪽 여백 16px, 상단 safe-area를 유지한다. 기본 색은 연한 회색이며 hover/키보드 초점에서 조금 진해진다.
- 음성 인식 엔진, 백엔드, PR, 배포는 변경하지 않았다. 모바일에서 발견한 아래 항목은 사용자에게 먼저 보고할 수정 후보다.

## 음성 검증 경계

설치된 Google Chrome의 실제 SpeechRecognition에 준비한 한국어 WAV를 AudioContext의 오디오 트랙으로 전달했다. 중간 전사와 최종 결과 `오늘 친구와 산책을 해서 기분이 좋았어요`를 확인했고, 실제 프론트 어댑터를 통해 로컬 계약 테스트 서버에 전송되어 감정 선택 카드로 진행했다. 이 검사에서 인식 결과 이벤트를 가짜로 주입하지 않았다.

물리 마이크, iPhone Safari·갤럭시·웨일의 실제 전사, 운영 서버 상담 품질, QR로 열린 배포 주소의 연결을 검증한 것은 아니다. UI 회귀 검사는 별도의 인식 이벤트 fixture를 사용한다. 처음 fake-device 방식으로 얻은 짧고 잘못된 인식 결과는 정확한 한국어 전사 성공 근거에서 제외했다.

재현은 별도 native-chrome 프로젝트와 `NATIVE_SPEECH_WAV`에 동일 시험 문장 WAV 경로를 지정하는 방식이다. 개인 로컬 음원·진단 결과는 Git에 넣지 않는다.

## 모바일 범위

Chromium/WebKit에서 작은 화면, 노치가 있는 화면, Android 크기, 가로 화면을 검사했다. CSS 안전 여백을 주입하고 주소창으로 줄어든 높이를 가정했다. 로그인/이메일/가입, 메인/메뉴/대화 진입, 말랑이 3종, 채팅/음성/안내/감정 입력/종료, 결과, 보관함 월간·주간·목록, 상세·대화 원문·기록 관리, MY·이용 안내·도움 연결, 수면 준비·설정·실행을 포함한다.

키보드는 viewport 높이를 줄여 재현했다. 실제 OS 키보드 및 Safari 주소창 움직임과 동일하다고 간주하지 않는다. 이전 스플래시·인증 왕복 검사는 docs/qa.md의 로그인 진입 항목에 별도로 남아 있다.

추가 음성 UI 관찰: 감정 카드 선택 중 인식기를 쉬게 하는 상태에서도 하단 음성 상태가 `마이크를 연결하고 있어요`로 표시된다. 실제 연결 실패가 아니라 ready=false 상태이며, 다음 수정에서 선택 대기 문구로 구분하는 것이 좋다.

## 오탐과 미확인 범위

- 수면 실행의 3px scrollWidth 차이는 잘리는 조작부가 아니라 의도적으로 바깥까지 퍼지는 장식 광원이다. 화면은 overflow:hidden으로 제어하며 가로 스크롤을 유발하지 않는다.
- 기록 상세의 하단 버튼은 본문 스크롤 영역에 있다. 첫 화면 경계에 걸친 것만으로 고정 버튼이 가려진다고 판단하지 않는다.
- Windows WebKit 동시 실행 중 page/context 종료가 발생했다. 열린 모달을 닫고 이동하는 사용자 경로로 정리하고 직렬 실행해 재검사했다. 최종 결과만 docs/qa.md에 기록한다.
- 실제 QR/모바일 배포 주소는 아직 검사하지 않았다. 배포 후 실제 iPhone·갤럭시에서 주소창 접힘/펼침, 노치/홈바, 키보드, 회전, 마이크 권한·전사를 확인해야 한다.
