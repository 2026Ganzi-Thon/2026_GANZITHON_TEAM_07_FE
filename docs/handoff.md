# 프론트엔드 인수인계

## 말랑이 재질 업데이트 · 2026-11-18

버터 원화 교체, 하트의 전체 파괴 후 조작 흐름 통일, 제공 음원과 움직임에 반응하는 슬랑이 지속음을 반영했다. 최종 동작·코드·출처·재현 절차는 [변경 명세](design/material-refresh-2026-11-18.md)를 따른다. 최종 확인한 왁뿌볼 추출 WAV3개를 프로젝트에 포함해 일반 실행과 로컬의 소리를 통일했다. 별도 환경변수나 원본 영상은 실행에 필요하지 않다.

## 현재 상태와 남은 작업

9개 경로의 화면을 연결했지만 실제 AI·인증·영속 DB는 연결하지 않았다. 기본 실행과 빌드는 MSW 예시 응답을 사용한다. 기록은 현재 탭의 메모리에만 남고 새로고침하면 초기화된다.

## 실행과 검증

Node >=22.12.0, npm 잠금 파일을 사용한다.

```sh
npm ci
npm run dev
npm run build
npm test
npx playwright install chromium webkit
npm run test:e2e
```

기본 주소는 http://127.0.0.1:5173 이다. `.env.example`은 mock 모드이며 환경 파일 없이도 동작한다. `VITE_API_MODE=real`은 구현 전이므로 서버 주소만 바꾸면 연동되는 상태가 아니다. Playwright 결과 경로는 `QA_OUTPUT_DIR`, 브라우저 위치는 `PLAYWRIGHT_BROWSERS_PATH`로 별도 지정할 수 있다.

1. 메인에서 말랑이를 누르면 페이지 이동 없이 체험한다. 처음부터 세 종류·각3개 모양을 선택할 수 있고 기본 대표는 양 스퀴시다.
2. 하단 탭/위로 쓸어올리기 또는 감정 기록 메뉴에서 같은 대화 시트를 연다. 첫 입력은 체험 계정 선택 뒤 대화에 전달된다.
3. 감정·사전 점수·생각·실천·사후 점수를 거쳐 결과를 확인한다. 의미 있는 한 글자 단어도 허용하며 수동 '이 내용으로 계속하기' 버튼은 없다.
4. 종료 확인에서는 계속 대화, 정상 마무리, 여기까지 보관, 저장 없이 나가기를 구분한다. 응답 실패 상태에서는 정상 완료를 막되 전송한 이야기의 중간 보관은 가능하다.
5. 결과 후보를 누르면 강조/이미지/CTA만 바뀐다. CTA에서 체험으로 이동하며 추천 기록 자체는 바꾸지 않는다.
6. 보관함 상세·삭제·가리기·MY 복원·계정 전환을 확인한다. 설정 뒤로가기는 출발 페이지와 보기 상태를 복원한다.

## 변경된 화면·상호작용

- 메인 상단은 기존 선택 버튼 높이(일반 화면80px+safe area)에 종류·소리·메뉴를 맞춘다. 메인 하단은 체험 마치기만 중앙에 두고 초기화는 제거했다. 독립 `/malangi` 화면의 초기화는 유지한다.
- 상단 메뉴는168~184px 반응형 폭,10px 내부 여백,6px 행 간격이다. 아이콘과 문구를 버튼 안에서 함께 중앙 정렬한다. Union PNG는 형태 참고용이며 실제 배경은 반투명/blur CSS다.
- 슬랑이/스퀴시는 접촉 위치를 중심으로 변형하고 손을 떼면 복원된다. 버터·하트·구름은 터치한 조각만 깨지고 이미 깨진 곳을 눌러 다른 조각을 깨지 않는다. 전체 파괴 후 안쪽 조작과 대기 후 껍질 재생을 반복한다.
- 하트도 버터처럼 누른 조각만 파괴하고 전부 깨진 뒤 안쪽을 조작한다. 손 떼기 즉시 껍질이 돌아오지 않으며 대기 후 전체 복원된다. 꾹 누르기만으로 파열음이 반복되지 않는다.
- 추천 배경은 #FFF9F2다. 제목의 기존 표시 서체는 유지하고 남은 문장 영역은 Pretendard(라벨500/본문600)를 사용한다. 짧은 내용은 기록 확인 링크까지 첫 화면에 노출하고 긴 내용은 스크롤한다.
- 감정 PNG12종은 주간 캘린더와 기록 목록에 사용한다. 동일 날짜는 최근 감정+복수 기록 배지, 가린 기록은 기본 목록/집계 제외다. 스트레스·미선택·미등록은 중립 표시이며 명시적 모르겠음 이미지와 구분한다.

## 음성 입력 경계

사용자 입력만 음성으로 받고 테스는 텍스트로 답한다. TTS/답변 읽기는 없다. 중간 전사는 음성 화면과 채팅의 임시 말풍선을 갱신하고, 확정 문장만 공통 send 경로로 한 번 전송한다. 응답 대기/선택 카드 단계에서는 인식을 멈추고 다음 자유 입력에서 재개한다.

채팅 보기는 음성 입력을 유지한다. 음소거는 듣기만 멈추며 중단은 텍스트 입력으로 돌아간다. 미확정 전사/작성 중 글은 초안으로 보존하고 상담 기록에 임의로 저장하지 않는다. 마이크 확인은 입력 레벨만 측정하며 녹음 파일을 저장·업로드하지 않는다.

실제 환경에서 마이크 입력 신호는 확인했으나 브라우저 인식 서비스 network 오류/무응답은 해결 확인되지 않았다. 가상 중간·최종 전사 이벤트 QA를 실제 한국어 인식 성공으로 해석하지 않는다. 백엔드 STT 계약과 공급자 연결이 필요할 수 있다.

## 코드 위치와 작성 규칙

| 위치 | 책임 |
|---|---|
| `src/main.tsx`, `App.tsx` | MSW 시작, QueryClient·Provider·경로·가시 높이 |
| `src/features/home/` | 메인·인라인 말랑이 상태(시트는 chat의 공유 컴포넌트) |
| `src/features/chat/` | 대화 reducer·타입·입력 카드·Chat·VoiceView·useVoice |
| `src/features/records/Records.tsx`, `Archive.tsx` | 결과·상세, 별도 Archive 구현을 Records에서 재수출 |
| `src/features/account/Account.tsx` | Login·Settings·Help. 실제 인증이 아닌 체험 계정 UI |
| `src/features/toy/` | 조작·Canvas 렌더러·물성·모양·오디오 |
| `src/lib/api.ts`, `contracts.ts` | fetch·제한 시간·응답 타입 검사·API 어댑터 |
| `src/lib/PreviewContext.tsx` | 체험 인증 진입, 대화 초안·완료 draft·오류 재현 상태 |
| `src/mocks/` | 결정적 대화 fixture, 메모리 저장소·MSW handler |
| `src/components/`, `src/styles/` | 공통 UI·CSS Modules·색상 토큰 |

- React 함수 컴포넌트·TypeScript strict·타입 전용 import를 사용한다. 컴포넌트는 PascalCase, hook은 use 접두사, 타입은 PascalCase로 작성한다.
- 현재 파일 형식은 작은따옴표·세미콜론·2칸 들여쓰기를 사용한다. Prettier/ESLint는 아직 설정하지 않았다. 큰 자동 포맷 변경과 기능 변경을 같은 PR에 섞지 않는다.
- 화면 스타일은 CSS Modules, 공통 색은 `src/styles/tokens.css`로 관리한다. CSS 파일을 다른 화면에서 사용하는 곳이 있어 삭제 전 import를 확인한다.
- 서버 상태는 TanStack Query, 대화는 reducer, 화면 내부 상태는 지역 state로 관리한다. 화면 컴포넌트에 새 fetch 호출을 직접 추가하지 않는다.
- 오류는 `ApiError`와 응답 검증을 거친다. 저장/삭제/HTTP 실패의 자동 반복을 추가하지 않는다. 잘못된 대화 응답만 같은 requestId로 한 번 재요청한다.
- `Records`는 `Chat`의 EmotionSummary와 CSS를 재사용하며 `Home`은 toy 조작 모듈을 공유한다. 기능별 PR은 이 의존 순서에 따라 분리한다.

## 백엔드 연결 지점

현재 아래 경로는 **프론트 전용 mock 경로**이며 백엔드 API 명세가 아니다.

| 프론트 호출 | mock 요청 | 연동 시 확인 |
|---|---|---|
| me/login/logout | `/__preview__/me`, `/login`, `/logout` | 실제 인증 방식·쿠키/토큰·세션 복구·계정 캐시 초기화 |
| reply | `/__preview__/messages` | 서버 stage와 프론트 Stage 변환, 중간 입력, 종료·위험 상태, 중복 요청 처리 |
| save | `POST /__preview__/records` | 완료/중단 API 순서, 전체 대화·사후 null·결과 ID, 저장 멱등성 |
| records/record/deleteRecord | `/__preview__/records[/:id]` | 조회 DTO·날짜/시간대·페이지네이션·삭제 범위·소유권 |
| setRecordHidden | PATCH /__preview__/records/:id | 가리기/복원 지원 여부, 본인 기록 권한, 목록·집계 제외 정책 |
| inventory/selectToy | `/__preview__/inventory` | 서버 종류 enum과 매핑, 세 종류 처음부터 개방하는 정책 |

표의 `/login` 등 축약 경로도 실제 코드에서는 모두 `/__preview__/` 아래에 있다. 실제 어댑터를 추가할 때 `main.tsx`의 mock-only 부팅과 `request()`의 경로를 함께 변경하고, 운영 응답을 `contracts.ts`의 프론트 모델로 변환한다. **PreviewRequest/Reply를 서버의 확정 DTO로 취급하지 않는다.**

현재 기본 예시 단계는 OPEN → EMOTIONS → PRE → THOUGHT → ACTION → POST → DONE이다. REFRAME/NEED/COPING 타입과 처리기는 유지하지만 기본 체험에서는 추가 질문하지 않는다. 백엔드의 단계명/완료 조건과 1:1이라고 가정하지 않는다. `SAMPLE_EMOTIONS`, 추천 매핑, 위험 표현 정규식도 운영 규칙이 아니다.

완료 draft는 전체 메시지를 포함한다. 현재 Result는 조회 hook에서 예시 멱등 저장을 호출하므로 실서버에서는 완료 명령과 결과 조회를 분리해 계약에 맞춘다. `Inventory.unlocked`는 호환 필드로 남아 있지만 예시 인벤토리는 모든 종류를 제공한다. 실제 서버의 기존 해금 규칙은 별도로 조율한다.

## 자산·오디오·서체

- 이미지9종과 감정12종, 음성 석상/채팅 아이콘, MY 프로필을 연결했다. 파일 출처·해시는 [자산 문서](assets.md), 화면별 연결은 [적용표](design/asset-handoff.md)를 따른다.
- 기본 효과음은 ON, 음량35%이며 첫 사용자 조작 이후에만 재생한다. 음소거·음량0·이탈·숨김에서 재생과 복원음/반복 예약을 정리한다. 기존 및 신규 WAV 표본의 출처와 가공 정보는 `public/assets/audio/LICENSES.md`와 manifest에 있다.
- 현재 기본 음원은 슬랑이MP3 1개와 스퀴시/복원/왁뿌볼 WAV9개다. 왁뿌볼 WAV는 최종 영상 추출본이며 일반 실행·빌드에 동일하게 포함된다. 가공 절차는 위 변경 명세를 따른다.
- 꾹꾹체는 기존 적용을 유지한다. 공식 안내에서 확인한 웹 임베딩/재배포 제한과 최종 배포 전 대체 서체·파일/이력 정리 협의는 [자산 문서](assets.md)를 따른다. 이번 병합은 공개 배포 허가 확인을 의미하지 않는다.
