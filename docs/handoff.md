## 현재 적용 — D39 (2026-11-16)

- **대화 진행:** 프론트 예시 응답의 사건 단어 목록/9자 제한을 제거했다. 보통 문장은 감정 선택으로 진행하고, 명백히 막연한 첫 문장은 한 번만 더 묻는다. 다음 의미 있는 답은 진행하며 ‘이 내용으로 계속하기’도 제공한다. 자음·기호만 입력하면 전송 전 입력창에서 안내하고 반복 AI 질문을 추가하지 않는다. 사용자 문장만 보관하며 서버의 사건 판단 규칙을 확정한 변경은 아니다.
- **종료 확인:** 보관은 진한 기본 버튼, 계속 대화는 테두리 버튼, 저장 없이 나가기는 구분선 아래 붉은 보조 동작이다. 감정 선택 후에는 점수 마무리도 유지한다. 저장 없이 나가기는 어떤 단계에서든 현재 대화를 보관하지 않고 메인으로 이동한다. 대화의 단계 캡션과 하단 ‘전문 상담이나 치료를 대신하지 않아요.’ 문구는 제거했다.
- **기록 상세:** Figma ‘마음 보관함 기록 선택’ 구성에 맞춰 요약·전후 점수·입력한 생각/실천을 한 카드에 넣고, 하단에 숨기기·삭제·자세히 보기를 배치한다. 상단 삭제와 외부 가리기 버튼은 제거했다. `?view=conversation`은 같은 기록의 전문 보기 상태이고 뒤로가기로 요약에 복귀한다. 가린 내용 보호·MY 복원·집계 제외는 유지한다. 없는 점수/관점/사용 이력은 생성하지 않는다.
- **메인 말풍선:** 투명 캔버스 경계 대신 양의 실제 보이는 상단을 기준으로 붙인다. 아이보리 둥근 면·작은 꼬리·얕은 그림자, 0.55초 등장과 4.8초 주기의 3px 떠오름을 적용한다. 호흡은 그림에만 적용해 클릭 영역을 고정하고 줄인 모션에서는 정지한다. 새 말풍선 모양/모션은 승인된 웹 보완안이며 Figma 원본 효과를 측정해 복제한 값은 아니다.
- **음성 경계:** 실제 사이드패널 브라우저에서 인식 서비스 `network` 오류를 재현했다. 시작 이벤트가 10초간 없으면 연결 대기를 끝내고, 결과 없는 종료의 자동 재시작은 1회로 제한한다. 오류 시 경과시간을 멈추고 초안을 보존하며 재시도/글로 계속하기를 제공한다. 브라우저 서비스 연결 실패 자체는 해결 확인되지 않았다. 실제 전사 성공·한국어 인식 품질과 가상 이벤트 QA를 구분한다.
- **범위:** 로그인 전체 흐름·수면은 변경하지 않았다. 실제 AI·인증·영속 DB/STT 백엔드 미연동, 기록은 현재 탭 메모리다. 독립 경로는 9개다. 노션/Figma 원본과 원격 Git은 수정하지 않는다.

## 이전 적용 — D38 (2026-11-16)

- **중간 보관:** 종료 확인창의 ‘여기까지 보관하고 나가기’는 전송한 사용자 메시지가 있을 때만 제공한다. 현재 대화·확정 감정·점수·슬롯을 그대로 저장하고 마음 보관함으로 이동한다. 감정 미선택도 허용하되 추천은 생성하지 않는다. 미입력 점수/슬롯을 채우지 않으며, 작성 중 글·미확정 음성은 저장하지 않는다. 저장 실패 시 대화를 유지하고 같은 ID/스냅샷으로 재시도한다. 정상 완료·사후 점수 경로도 유지한다.
- **기록 가리기:** 삭제와 별도다. 가린 기록은 월간·주간·목록·횟수/평균/감정 집계에서 제외한다. MY → 기록 관리 / 삭제 / 가리기에서 확인하고 다시 표시할 수 있다. 가린 상세는 내용 대신 안내를 먼저 보여주고 ‘이번에만 내용 보기’로 펼친다. 별도 잠금/암호 보호를 뜻하지 않는다.
- **말랑이 선택:** 추천받은 종류가 기본 선택이다. 후보를 누르면 같은 결과 화면의 강조·캐릭터·조작 안내·CTA만 바뀐다. ‘선택한 말랑이 만지러 가기’에서 이동하며 당시 추천 기록은 유지한다. ‘눌러서 바꿀 수 있어요’를 표시한다.
- **짧은 프론트 대화:** 기본 예시 경로는 OPEN → EMOTIONS → PRE → THOUGHT → ACTION → POST → DONE이다. REFRAME/NEED/COPING 타입과 기존 분기 처리는 남기지만 기본 체험에서 추가 질문하지 않는다. 건너뛴 슬롯은 미입력으로 유지한다. 이 변경은 서버 AI 단계 정책의 확정이 아니다.
- **화면:** 음성 석상은 상단 최소72px(낮은 화면64px)을 확보하고 메인 말풍선의 박스 기준 배치는 D39에서 실제 양 그림 기준으로 교체했다. 추천 카드/요약/후보/CTA는 고정 Y 대신 내용 높이를 따라 배치한다. 작은 조언은 산책·휴식·기록 각 3개 문구와 해당 원본 SVG를 연결하며, 사용자 실천이 있으면 그 문장을 우선한다.
- **경계:** 로그인 전체 흐름과 수면은 기존 임시 상태를 유지한다. 실제 AI·인증·영속 DB 미연동. 중간 저장 `partial`, 가리기 `hidden`, PATCH는 프론트 예시 계약이며 서버 지원을 의미하지 않는다. 새로고침하면 체험 기록은 초기화된다. 독립 경로 수는 9개이며 `/archive?manage=1`은 보관함의 관리 상태다.


갱신: 2026-11-16. 이 문서는 현재 로컬 구현을 넘겨받아 API 연결과 남은 화면을 작업하는 개발자를 위한 안내다. PRD는 목표 사양, 이 문서와 구현 현황은 실제 코드 상태를 설명한다.

## 실행과 화면 확인

Node 24에서 검증했다. package.json의 최소 버전은 22.12.0이며 의존성 설치는 잠금 파일을 사용하는 `npm ci`로 한다.

```sh
npm ci
npm run dev
```

기본 주소는 http://127.0.0.1:5173 이다. 환경 파일 없이도 mock 모드로 실행하며 `.env.example`을 참고할 수 있다. `VITE_API_MODE=real`은 구현되어 있지 않아 부팅 오류가 난다. 서버 주소만 바꾸면 연동되는 구조는 아니다.

1. 메인 말랑이를 누르면 같은 화면에서 조작한다. 비로그인 상태에서도 세 종류 선택이 가능하다.
2. 메뉴 → 감정 기록 → 첫 입력/대화 시작. 체험 계정 선택 후 첫 메시지와 목적지를 이어받는다.
3. 구체적인 상황을 입력하거나 시작 예시를 선택한다. 대표 감정 1개는 필수, 부가 감정은 선택이다. 현재 6개 감정은 테스트용 목록이다.
4. 사전 강도 선택 → 대화 → 끝내기 → 사후 강도 또는 건너뛰기 → 결과. 별도로 ‘여기까지 보관하고 나가기’를 선택하면 감정 선택 전에도 현재 대화만 저장한다. 감정 선택 전 ‘저장 없이 나가기’는 결과 없이 종료한다.
5. 결과가 생기면 말랑이를 만지지 않아도 보관함에 보인다. 상세 대화 조회·삭제·계정 전환을 확인한다.
6. 대화 마이크 버튼으로 음성 모드를 연다. 지원 브라우저/권한/HTTPS가 필요하다. UI의 오류 재현 스위치는 제거했고 테스트에서만 fetch 실패를 주입한다 (`tests/support/faults.ts`).

## 코드 위치와 작성 규칙

| 위치 | 책임 |
|---|---|
| `src/main.tsx`, `App.tsx` | MSW 시작, QueryClient·Provider·경로·가시 높이 |
| `src/features/home/` | 메인·진입 시트·인라인 말랑이 상태 |
| `src/features/chat/` | 대화 reducer·타입·입력 카드·Chat·VoiceView·useVoice |
| `src/features/records/Records.tsx`, `Archive.tsx` | 결과·상세, 별도 Archive 구현을 Records에서 재수출 |
| `src/features/account/Account.tsx` | Login·Settings·Help. 실제 인증이 아닌 체험 계정 UI |
| `src/features/toy/` | 조작·Canvas 렌더러·물성·모양·오디오 |
| `src/lib/api.ts`, `contracts.ts` | fetch·제한 시간·응답 타입 검사·API 어댑터 |
| `src/lib/PreviewContext.tsx` | 체험 인증 진입, 대화 초안·완료 draft·오류 재현 상태 |
| `src/mocks/` | 결정적 대화 fixture, 메모리 저장소·MSW handler |
| `src/components/`, `src/styles/` | 공통 UI·CSS Modules·색상 토큰 |

- React 함수 컴포넌트·TypeScript strict·타입 전용 import를 사용한다. 컴포넌트는 PascalCase, hook은 use 접두사, 타입은 PascalCase로 작성한다.
- 현재 파일 형식은 작은따옴표·세미콜론·2칸 들여쓰기를 사용한다. Prettier/ESLint는 아직 설정하지 않았다. 큰 자동 포맷 변경과 기능 변경을 같은 PR에 섞지 않는다.
- 화면 스타일은 CSS Modules, 공통 색은 `src/styles/tokens.css`로 관리한다. CSS 파일을 다른 화면에서 사용하는 곳이 있어 삭제 전 import를 확인한다.
- 서버 상태는 TanStack Query, 대화는 reducer, 화면 내부 상태는 지역 state로 관리한다. 화면 컴포넌트에 새 fetch 호출을 직접 추가하지 않는다.
- 오류는 `ApiError`와 응답 검증을 거친다. 저장/삭제/HTTP 실패의 자동 반복을 추가하지 않는다. 잘못된 대화 응답만 같은 requestId로 한 번 재요청한다.
- `Records`는 `Chat`의 EmotionSummary와 CSS를 재사용하며 `Home`은 toy 조작 모듈을 공유한다. 기능별 PR은 이 의존 순서에 따라 분리한다.

## 백엔드 연결 지점

현재 아래 경로는 **프론트 전용 mock 경로**이며 백엔드 API 명세가 아니다.

| 프론트 호출 | mock 요청 | 연동 시 확인 |
|---|---|---|
| me/login/logout | `/__preview__/me`, `/login`, `/logout` | 실제 인증 방식·쿠키/토큰·세션 복구·계정 캐시 초기화 |
| reply | `/__preview__/messages` | 서버 stage와 프론트 Stage 변환, 중간 입력, 종료·위험 상태, 중복 요청 처리 |
| save | `POST /__preview__/records` | 완료/중단 API 순서, 전체 대화·사후 null·결과 ID, 저장 멱등성 |
| records/record/deleteRecord | `/__preview__/records[/:id]` | 조회 DTO·날짜/시간대·페이지네이션·삭제 범위·소유권 |
| setRecordHidden | PATCH /__preview__/records/:id | 가리기/복원 지원 여부, 본인 기록 권한, 목록·집계 제외 정책 |
| inventory/selectToy | `/__preview__/inventory` | 서버 종류 enum과 매핑, 세 종류 처음부터 개방하는 정책 |

표의 `/login` 등 축약 경로도 실제 코드에서는 모두 `/__preview__/` 아래에 있다. 실제 어댑터를 추가할 때 `main.tsx`의 mock-only 부팅과 `request()`의 경로를 함께 변경하고, 운영 응답을 `contracts.ts`의 프론트 모델로 변환한다. **PreviewRequest/Reply를 서버의 확정 DTO로 취급하지 않는다.**

현재 기본 예시 단계는 OPEN → EMOTIONS → PRE → THOUGHT → ACTION → POST → DONE이다. REFRAME/NEED/COPING 타입과 처리기는 유지하지만 기본 체험에서는 추가 질문하지 않는다. 백엔드의 단계명/완료 조건과 1:1이라고 가정하지 않는다. `SAMPLE_EMOTIONS`, 추천 매핑, 위험 표현 정규식도 운영 규칙이 아니다.

완료 draft는 전체 메시지를 포함한다. 현재 Result는 조회 hook에서 예시 멱등 저장을 호출하므로 실서버에서는 완료 명령과 결과 조회를 분리해 계약에 맞춘다. `Inventory.unlocked`는 호환 필드로 남아 있지만 예시 인벤토리는 모든 종류를 제공한다. 실제 서버의 기존 해금 규칙은 별도로 조율한다.

## 디자인·자산 인계

- 최신 Figma가 시각 기준이다. [직접 확인한 치수](design/figma-inspection-2026-11-15.md)와 [자산 수령·적용표](design/asset-handoff.md)를 참고한다.

- 말랑이 자산 교체 지점은 ToyCanvas/ToySurface/paintToy와 결과 화면의 Malangi다. 정적 이미지 교체만으로 국소 변형이 유지되지 않으므로 렌더러와 조작 hook의 연결을 함께 검수한다.
- Pretendard와 음원은 배포 라이선스를 동봉했다. 제공 꾹꾹체는 메뉴·MY 항목·추천 제목·동적 요약에만 로컬 적용했다. 공개 배포 사용 조건은 미확인이다. 출처는 [assets.md](assets.md)에 있다.
- 수면 설정 PNG를 제공받았다는 사실은 수면 기능 구현 완료가 아니다. 전체 화면을 이미지로 덮어 구현하지 않는다.

## D36 인계 — 메인과 보관함

- `Home.tsx`: 하단 탭/상향 40px 이상 제스처로 기존 시트 진입. 가로/하향 드래그로 열리지 않는다. 닫기 후 초안과 초점을 유지한다. 첫 입력을 넘긴 뒤 기존 로그인/전체 대화 경로로 이동한다.
- `AppMenu.tsx`: 메인은 `placement="top"`으로 아래 방향 팝업. 독립 말랑이 화면은 기존 하단 위치 유지. 두 메뉴 모두 수면 모드/감정 기록/마음 보관함/설정·MY를 제공한다. 수면은 준비 안내다.
- `Archive.tsx`/`Archive.module.css`로 보관함을 분리했다. `Records.tsx`에서 재수출하므로 라우트 변경은 없다. `archiveModel.ts`에 월~일 날짜·평균·이모지 표시 규칙이 있다.
- 날짜는 현재 브라우저 로컬 날짜다. 주간은 월 경계를 포함한 실제 7일이며 최근 기록의 대표 감정, 같은 날 복수 기록 개수를 표시한다. 평균은 전후 점수가 모두 입력된 기록만 사용하며 0은 유효하다. 기간 내 기록이 없거나 점수 쌍이 없으면 ‘—’다. 서버 시간대/페이지네이션은 연동 시 확정해야 한다.
- 이모지는 `emotionPresentation`에서 교체 가능하다. 이미지 수령 전 임시 표시이며 목록 전체가 최종 감정 enum이라는 뜻은 아니다.
- 예시 AI 발화와 reducer의 안내 발화에 하오체를 적용했다. 단계 로직·사용자 입력·일반 버튼·위기 안내는 바꾸지 않았다. 실제 AI 프롬프트 적용은 백엔드 연동 작업이다.
- [디자인 적용값과 원본 확인 범위](design/navigation-archive-2026-11-16.md), [QA](qa.md)를 확인한다. 원본 SVG 미수령 아이콘은 Lucide 기반이며 원본과 완전 동일하다고 간주하지 않는다.

## D37 인계 — 대화 입력과 음성

- `Chat.send()`로 시트 첫 입력·직접 타이핑·시작 문구·확정 음성을 통일했다. 시작 문구는 보이는 문장을 그대로 전송한다. `PreviewRequest.history`는 로컬 OPEN 보충 입력에만 사용하며 서버 DTO로 확정하지 않는다.
- `src/mocks/dialogue.ts`는 사건 서술/직전 입력을 함께 참고하지만 정규식 fixture다. 실제 AI 판단·슬롯 추출·모든 자연어를 처리하는 엔진이 아니다. 백엔드 연결 시 이 판단을 클라이언트에 복제하지 않는다.
- `useVoice.ts`는 브라우저 인식·음성 합성 어댑터, `VoiceView.tsx`는 SC03 내부의 음성 보기다. 중간 전사는 `voice.interim`, 확정 문장은 기존 send로 한 번 전달한다. 준비된 카드에서는 인식을 멈추며 채팅 보기 전환으로 새 대화를 만들지 않는다.
- 종료/화면 내 뒤로가기는 확인창을 거친다. 취소는 초안/메시지/스크롤을 보존한다. 음성 중단 버튼은 상담 종료가 아니다.
- 미확정 발화는 음소거·중단·설정·종료 확인·탭 숨김에서 초안에 보존한다. 인식/TTS 콜백은 중단·이탈 시 해제하며 이전 콜백으로 메시지가 중복 생성되지 않게 한다.
- 브라우저 인식은 제공자 서버를 이용할 수 있다. HTTPS·지원 브라우저·권한이 필요하고 실제 기기/한국어 인식/TTS 검증은 남아 있다. 자동화의 가상 인식 이벤트 통과를 실기기 통과로 보고하지 않는다.
- 제품 UI의 개발 안내/오류 주입 스위치는 제거했다. 실제 AI·추천·인증·DB는 여전히 임시다. `tests/support/faults.ts`에서만 통신 오류를 재현한다. 로그인 전체 흐름·수면은 유지했고 회원정보/비밀번호는 비활성이다.
- `Profile`은 현재 `id`/`nickname`만 있다. Figma의 예시 이메일·생일·성별을 가짜로 채우지 않았다. 실제 필드 계약/빈값·긴이름 처리와 계정 기능은 로그인 담당 작업이다.
- 최신 원본 수치/아이콘 근사/소유 범위는 [D37 디자인 기록](design/dialogue-voice-2026-11-16.md), 검증은 [QA](qa.md)를 따른다.
