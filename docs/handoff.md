## 전사문 확인 후 전송·추천 모양 보존·모바일 보완 — 2026-11-20 최신

음성 입력은 **전사 → 입력창에서 확인/수정 → 직접 전송**이다. 확정 인식 결과도 자동 전송하지 않으며, 채팅 보기로 돌아오면 듣기를 멈춘다. 기존 작성 글에 이어 받아 적고 전송/오류/중단 뒤 늦게 온 인식 결과가 작성 내용을 덮어쓰지 않도록 한다. 안내는 우상단 ⓘ에서 이 흐름을 설명한다. 아래 과거 자동 전송 설명은 이 기준으로 대체한다.

이어하기/새 시작 버튼 문구와 상담 완료→결과 조회 로딩을 중앙 정렬했다. 회원가입 키보드/노치, 가로 메인·로그인, 수면 설정 손잡이의 안전 여백을 보완했다.

세부 추천 모양은 이번 변경 이후 이 브라우저에서 처음 결과를 확인할 때 계정·기록 ID·생성시각에 묶어 저장한다. 서버는 추천 종류만 반환하므로 로컬에는 모양 ID만 보관한다. 대화 내용/음성/토큰은 추가 저장하지 않는다. 후속 모양 변경·새로고침에도 당시 모양을 유지한다. 세부 정보가 없는 과거/다른 기기 기록에는 임의의 양 이미지를 역사적 추천으로 표시하지 않고 추천 종류만 표시한다. 기기 간 보존은 백엔드 필드 추가가 필요하다.

[변경 상세와 검증 경계](manual-voice-and-mobile-2026-11-20.md). 백엔드·PR·병합·배포 없이 로컬 검토 중이다.

## 모바일 QA·음성 안내 우상단 — 2026-11-20 후속

음성 안내 아이콘은 우상단의 연한 회색 18px ⓘ로 조정했다(44px 터치 영역 유지). 실제 Chrome에 준비한 한국어 오디오 트랙을 전달하여 정확한 전사 및 프론트 자동 전송을 확인했다. 물리 마이크나 휴대폰에서 성공했다는 의미는 아니다.

전체 화면 모바일 순회에서 회원가입 시트의 키보드/노치 대응, 가로 메인 하단 버튼의 safe-bottom 누락, 수면 설정 손잡이의 홈바 여유 부족, 가로 로그인 배치가 수정 후보로 확인됐다. 사용자에게 먼저 보고하는 단계이며 이 모바일 레이아웃 변경은 아직 반영하지 않았다. 상세와 실기기 미확인 범위는 [모바일·음성 점검](mobile-voice-audit-2026-11-20.md)을 따른다. PR·배포는 하지 않았다.

## MY·보관함·결과 제목·음성 안내 — 2026-11-20 최신

결과 제목은 ‘오늘 나눈 이야기’로 변경하고 서버 keySentence/summary 선택 및 본문은 그대로 유지한다. 보관함 최초 조회의 로딩 표시만 제목/날짜 아래 남은 본문 중앙에 배치하며 일반 로딩 컴포넌트·오류·빈 목록 배치는 변경하지 않는다.

MY는 닉네임과 간격을 둔 ‘님’, 실제 계정 이메일을 표시한다. 로그인 응답에는 이메일이 없으므로 MY 진입 시 기존 auth/me를 통해 공유 프로필을 갱신한다. 생년월일·나이·성별·직업·가짜 이메일은 표시하지 않는다. 배포 명세에 수정/재설정 API가 없는 회원정보 수정·비밀번호 찾기/변경 메뉴는 제거했다. 백엔드 기능이 구현된 것은 아니다.

채팅 헤더의 설정 버튼을 제거하고 음성 화면 우상단에 ⓘ 안내 버튼을 둔다. 터치 영역은 44px, 아이콘은 18px이며 연한 회색으로 표시한다. real/mock은 같은 VoiceView를 사용한다. ‘음성 입력 안내’에는 전사문 확인·수정 후 직접 전송하는 방법을 짧게 설명한다. 안내 중 인식 대기와 닫은 뒤 재개 정책을 유지하며 WebKit에서도 닫은 뒤 안내 버튼에 초점을 복원한다. 음성 인식 엔진이나 서버는 변경하지 않았다.

PR·병합·배포 없이 로컬 검토 상태다. 검증 근거는 docs/qa.md의 같은 날짜 항목을 따른다.

## 로그인 → 스플래시 → 메인 — 2026-11-20 최신

공개 도움말의 프로필 조회는 비활성화했다. 문서 단위 뒤로/앞으로 이동 중 불필요한 refresh 회전이 중단되어 세션이 풀리던 경우를 수정했고 양 브라우저에서 재검사했다. 인증 지연/실패→재시도와 일반 페이지 왕복도 확인했다. 명시적 mock 작업대는 기존 예시 동작을 유지하며 새 진입 계약은 기본 real 모드에 적용한다.

AppEntry에서 인증을 먼저 확인한다. 첫 방문에는 로그인, 성공 뒤에는 제공 시안의 양/동동체 스플래시를 거쳐 메인으로 이동한다. 같은 탭의 로그인 유지·새로고침·직접 링크 복귀를 유지하고, 일반 내부 이동에는 스플래시를 반복하지 않는다. 로그인 우회 링크를 제거하고 로그아웃은 로그인으로 replace한다. 준비 화면은 history에 넣지 않는다. 수면 실행 배경은 제공 캡처 기준으로 중성 차콜 그라데이션과 빛 번짐을 다시 맞췄다. [진입/배경 상세](design/login-splash-entry-2026-11-20.md), [검증](qa.md). 서버 변경·PR·배포 없이 로컬 검토 중이다.

실제 상담의 종료 팝업에서 정리/계속 버튼과 나가기 영역을 구분하고, ‘아직 보내지 않은 글’은 새 줄로 표시한다. ‘잠시 나가기’와 ‘저장 없이 나가기’는 같은 행에 배치했다. 감정 기록은 제출한 메시지 위치에 기본 접힘 상태로 남고 클릭·키보드로 펼친다. 후속 수면 작업에서 응답 대기/마지막 점수 안내까지 채팅 상단 문구를 모두 제거했다. 왁뿌볼은 새 껍질이 깨질 때만 140ms의 작은 시각 반동이 발생한다. 조작 좌표는 움직이지 않는 프레임 기준이며 모션 감소 설정을 존중한다. API·백엔드·결과 문장·음원은 변경하지 않았다.

후속으로 ‘잠시 나가기’를 선택한 같은 계정의 미완료 대화에만 이어하기 전용 시트를 표시한다. 재개는 기존 로그/작성 글을 유지하고 새 요청을 보내지 않는다. 새 시작은 저장 없이 종료할지 확인 후 기존 abort API 성공 때만 입력창을 연다. 실패 시 캐시를 보존하고 자동 반복하지 않는다. 감정 카드 화살표는 Lucide SVG로 교체했다. [변경 상세](chat-polish-2026-11-20.md), [QA](qa.md)를 따른다. PR·병합·배포 없이 로컬 검토 중이다.

## 실행과 검증

Node 24.x, npm 잠금 파일을 사용한다.

```sh
npm ci
npm run dev        # real 모드(기본, 2026-11-19~): 배포 백엔드로 이메일 로그인
npm run dev:mock   # 예시 데이터만 쓰는 mock 모드(백엔드 없이 체험 계정)
npm run build      # real 모드 빌드 (build:mock은 mock 모드 빌드)
npm test
npx playwright install chromium webkit
npm run test:e2e
```

기본 주소는 http://127.0.0.1:5173 이다. 환경 파일 없이도 동작한다.

**실행 모드(#13):** 기본 `npm run dev`는 **real 모드**다. 이메일 가입·로그인·로그아웃·프로필이 백엔드 `/api/v1/auth`를 호출한다. 상담·완료 기록도 실제 API를 사용한다. 말랑이 inventory만 MSW 로컬 선택 상태를 실제 계정 ID별로 나눈다. 백엔드 없이 예시만 쓰려면 `npm run dev:mock`(Vite `--mode mock`)을 쓴다. `VITE_API_MODE`를 직접 지정하면 그 값이 우선한다. Windows에서도 동작하도록 환경변수 접두 대신 `--mode`를 쓴다.
- **백엔드 배포 주소:** `https://malangi.up.railway.app` (Swagger: `/swagger-ui/index.html`). 2026-11-18 기준 헬스체크가 `UP`이고, API 목록이 백엔드 docs/api.md와 일치한다.
- 개발/preview 서버는 `/api`를 `VITE_API_PROXY_TARGET`(기본: 위 배포 주소)으로 프록시한다. 로컬 백엔드를 쓰려면 `VITE_API_PROXY_TARGET=http://127.0.0.1:8080`으로 바꾼다.
- **CORS:** 배포 서버는 `localhost:5173`만 허용하고 우리 개발 주소인 `127.0.0.1:5173`은 403으로 막는다. 그래서 프록시가 브라우저 Origin 헤더를 지운다.
- **Vercel 배포 준비(2026-11-20):** `VITE_API_BASE_URL`은 비우거나 생략한다. `vercel.json`의 `/api` 프록시가 Origin을 제거하고 Railway로 전달하며 API 캐시를 금지한다. Node는 24.x다. [설정·QA·미검증 경계](vercel-deployment.md). 프로젝트 생성/Git 연결/PR/배포는 아직 하지 않았다.
- **로그인 화면(SC09)**은 Figma 151:11030의 워드마크·석상·배치를 사용하며, 현재 진입 버튼은 **이메일 하나**다.
  - Apple, 전화번호 가입, 비밀번호 찾기/변경은 백엔드 API가 없어 숨긴다.
  - 이메일 로그인·가입 폼은 `BottomSheet` 안에 넣었다.
  - mock 모드는 같은 배치에서 체험 계정 A/B와 "체험 계정으로 계속하기"를 보여준다.
- 토큰 정책: Access 토큰은 메모리, Refresh 토큰은 `sessionStorage`(`teslang:refresh-token`)에 둔다. 같은 탭 새로고침은 로그인을 유지하고, 탭을 닫으면 끝난다. 로그·화면에 토큰을 남기지 않는다.
- 인증이 필요한 요청이 401이면 refresh를 한 번 하고 같은 요청을 딱 한 번 다시 보낸다. 동시 401은 refresh 하나를 공유한다. refresh가 거절되면 세션을 지우고 로그인 화면으로 보낸다. 이것이 백엔드 HTTP 실패에 대한 유일한 자동 재전송이다(401은 서버가 처리하지 않은 요청이라 저장·삭제가 중복되지 않는다). Playwright 결과 경로는 `QA_OUTPUT_DIR`, 브라우저 위치는 `PLAYWRIGHT_BROWSERS_PATH`로 별도 지정할 수 있다.

1. 메인에서 말랑이를 누르면 페이지 이동 없이 체험한다. 처음부터 세 종류·각3개 모양을 선택할 수 있고 기본 대표는 양 스퀴시다.
2. 하단 탭/위로 쓸어올리기 또는 감정 기록 메뉴에서 같은 대화 시트를 연다. 첫 입력은 체험 계정 선택 뒤 대화에 전달된다.
3. 감정·사전 점수·생각·실천·사후 점수를 거쳐 결과를 확인한다. 의미 있는 한 글자 단어도 허용하며 수동 '이 내용으로 계속하기' 버튼은 없다.
4. real 종료 확인은 계속 대화, 현재 탭에서 이어가기, 서버 단계에 따른 정상 마무리, 저장 없이 중단으로 구분한다. 서버 중간 보관으로 표시하지 않는다. mock의 여기까지 보관은 예시 데이터 전용이다.
5. 결과 후보를 누르면 강조/이미지/CTA만 바뀐다. CTA에서 체험으로 이동하며 추천 기록 자체는 바꾸지 않는다.
6. 보관함 상세·삭제·가리기·MY 복원·계정 전환을 확인한다. 설정 뒤로가기는 출발 페이지와 보기 상태를 복원한다.

## 변경된 화면·상호작용

- 메인 상단은 기존 선택 버튼 높이(일반 화면80px+safe area)에 종류·소리·메뉴를 맞춘다. 메인 하단은 체험 마치기만 중앙에 두고 초기화는 제거했다. 독립 `/malangi`도 같은 UI를 공유하며 초기화 버튼은 없다.
- 상단 메뉴는168~184px 반응형 폭,10px 내부 여백,6px 행 간격이다. 아이콘과 문구를 버튼 안에서 함께 중앙 정렬한다. Union PNG는 형태 참고용이며 실제 배경은 반투명/blur CSS다.
- 슬랑이/스퀴시는 접촉 위치를 중심으로 변형하고 손을 떼면 복원된다. 버터·하트·구름은 터치한 조각만 깨지고 이미 깨진 곳을 눌러 다른 조각을 깨지 않는다. 전체 파괴 후 안쪽 조작과 대기 후 껍질 재생을 반복한다.
- 하트도 버터처럼 누른 조각만 파괴하고 전부 깨진 뒤 안쪽을 조작한다. 손 떼기 즉시 껍질이 돌아오지 않으며 대기 후 전체 복원된다. 꾹 누르기만으로 파열음이 반복되지 않는다.
- 추천 배경은 #FFF9F2다. 제목은 Cafe24 동동체를 사용하고 남은 문장 영역은 Pretendard(라벨500/본문600)를 사용한다. 짧은 내용은 기록 확인 링크까지 첫 화면에 노출하고 긴 내용은 스크롤한다.
- 감정 PNG12종은 주간 캘린더와 기록 목록에 사용한다. 동일 날짜는 최근 감정+복수 기록 배지, 가린 기록은 기본 목록/집계 제외다. 스트레스·미선택·미등록은 중립 표시이며 명시적 모르겠음 이미지와 구분한다.

## 음성 입력 경계

사용자 입력만 음성으로 받고 테스는 텍스트로 답한다. TTS/답변 읽기는 없다. 중간 전사는 음성 화면과 채팅의 임시 말풍선을 갱신하고, 확정 문장만 공통 send 경로로 한 번 전송한다. 응답 대기/선택 카드 단계에서는 인식을 멈추고 다음 자유 입력에서 재개한다.

채팅 보기는 음성 입력을 유지한다. 음소거는 듣기만 멈추며 중단은 텍스트 입력으로 돌아간다. 미확정 전사/작성 중 글은 초안으로 보존하고 상담 기록에 임의로 저장하지 않는다. 마이크 확인은 입력 레벨만 측정하며 녹음 파일을 저장·업로드하지 않는다.

실제 환경에서 마이크 입력 신호는 확인했으나 브라우저 인식 서비스 network 오류/무응답은 해결 확인되지 않았다. 가상 중간·최종 전사 이벤트 QA를 실제 한국어 인식 성공으로 해석하지 않는다. 백엔드 STT 계약과 공급자 연결이 필요할 수 있다.

표의 `/login` 등 축약 경로도 실제 코드에서는 모두 `/__preview__/` 아래에 있다. 실제 어댑터를 추가할 때 `main.tsx`의 mock-only 부팅과 `request()`의 경로를 함께 변경하고, 운영 응답을 `contracts.ts`의 프론트 모델로 변환한다. **PreviewRequest/Reply를 서버의 확정 DTO로 취급하지 않는다.**

현재 기본 예시 단계는 OPEN → EMOTIONS → PRE → THOUGHT → ACTION → POST → DONE이다. REFRAME/NEED/COPING 타입과 처리기는 유지하지만 기본 체험에서는 추가 질문하지 않는다. 백엔드의 단계명/완료 조건과 1:1이라고 가정하지 않는다. `SAMPLE_EMOTIONS`, 추천 매핑, 위험 표현 정규식도 운영 규칙이 아니다.

완료 draft는 전체 메시지를 포함한다. 현재 Result는 조회 hook에서 예시 멱등 저장을 호출하므로 실서버에서는 완료 명령과 결과 조회를 분리해 계약에 맞춘다. `Inventory.unlocked`는 호환 필드로 남아 있지만 예시 인벤토리는 모든 종류를 제공한다. 실제 서버의 기존 해금 규칙은 별도로 조율한다.
