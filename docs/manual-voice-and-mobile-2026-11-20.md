# 전사문 확인 후 전송·추천 모양·모바일 보완 (2026-11-20)

## 동작

- 음성 interim/final 모두 작성 중 글만 갱신한다. 인식 확정만으로 채팅 메시지나 상담 요청을 만들지 않는다.
- 말하기 전 작성한 글 뒤에 전사를 붙이고 다음 발화도 이어 붙인다. 같은 발화의 수정 결과는 해당 부분을 갱신하며 중복 추가하지 않는다.
- 음성 화면은 전사된 이야기와 채팅에서 확인하라는 안내를 표시한다. 채팅 보기로 돌아오거나 입력창을 편집하면 듣기를 멈춘다.
- 사용자가 확인·수정한 뒤 전송 버튼을 누르면 인식을 종료하고 한 번 보낸다. 전송 뒤 자동으로 듣기를 재개하지 않는다. 다시 받아쓰려면 마이크를 켠다.
- 음소거/중단/권한·연결 오류/탭 숨김/대화 잠시 나가기에서 작성 중 글을 보존한다. 이전 인식기의 지연 이벤트는 무시한다. 2,000자를 넘긴 글은 자동 전송하거나 잘라 버리지 않고 편집하도록 남긴다.
- TTS는 없다. 브라우저 SpeechRecognition 지원/서비스 연결 한계를 해결했다고 주장하지 않는다.

## UI 보완

- ‘이전 대화 이어하기’와 ‘저장 없이 종료하고 새로 시작’ 버튼 문구 중앙 정렬. 화살표는 오른쪽에 독립 배치.
- 보관함 로딩과 별도로 실제 상담 완료 후 결과 조회의 ‘이야기를 마무리하고 있어요.’/spinner를 본문 중앙에 배치.
- 가입 시트 최대 높이 계산에 safe-top과 visualViewport offset을 반영하고 하단 여백도 safe-bottom 유지. WebKit의 resize 이벤트 적용 전에도 높이가 제한되도록 CSS 100dvh 상한을 함께 적용한다. 높이 변경/입력 초점 이동 뒤에는 해당 필드가 안전 영역 안에 보이도록 시트 내부 스크롤도 보정한다.
- 가로 메인 하단 CTA 안전 여백, 좁고 낮은 앱 프레임의 로그인 폭, 닫힌 수면 설정 손잡이 홈바 여백과 드래그 거리 수정.
- 감정 입력 카드 대기 중 음성 상태는 연결 중으로 오표시하지 않는다.

## 추천 모양 보존 범위

서버 기록에는 SLANGI/SQUISHY/WAKPPU 종류만 있고 세부 모양 필드는 없다. 결과에 실제로 표시한 모양을 계정/기록/생성시각별 메타데이터로 처음 한 번 저장한다. 결과·상세·체험 링크가 같은 ID를 사용한다. 9종 모두 현재 선호 모양을 바꿔도 기존 기록이 바뀌지 않는다.

localStorage 값에는 ArtworkId만 저장한다. 기록 원문·음성·감정·토큰을 추가 저장하지 않는다. 저장소가 막혀 있으면 현재 탭 메모리만 사용한다. 이전 기록이나 다른 기기에 모양 정보가 없으면 ‘당시 추천 종류’만 표시하며 임의의 양 이미지를 추천 이력으로 사용하지 않는다. 해당 상태의 ‘말랑이 만나기’는 그 종류의 기본 모양으로 시작한다.

백엔드를 수정하지 않았으므로 기기 간 보존/저장소 삭제 후 복원은 미지원이다. 이후 서버에 세부 모양 ID를 저장하려면 별도 API 변경이 필요하다. 과거 기록의 실제 모양을 추측해 복구하지 않는다.

## 검증

실제 설치 Chrome 음성 인식 검사와 주입 이벤트 UI 검사, 테스트 API 계약 검사, 모바일 크기 시뮬레이션을 구분한다. 실물 iPhone/갤럭시 마이크, 운영 API 대화, QR 배포 접속은 이번 로컬 자동화의 검증 범위가 아니다.

- TypeScript/Vite 빌드 통과, 단위 158개/19파일 통과.
- 음성 UI 회귀: Chromium 14개 통과, WebKit 14개 통과(마이크 진단 1개는 독립 실행 재검증 포함). 중간/최종 전사·기존 초안·여러 발화·수정·수동 전송·중단/실패/빈 결과·늦은 이벤트·권한 정리를 포함한다. 이 검사는 인식 이벤트 fixture 기반이다.
- 별도 설치 Chrome의 실제 SpeechRecognition에 한국어 WAV 트랙을 전달해 ‘오늘 친구와 산책을 해서 기분이 좋았어요’의 최종 인식을 확인했다. 채팅 초안 확인 전 상담 세션 POST 0회, 직접 전송 후 1회 및 감정 카드 표시를 검증했다. 실제 서버 대신 로컬 계약 테스트 서버를 사용했다. 실제 휴대폰 마이크 테스트는 아니다.
- 실제 프론트 API 어댑터+로컬 계약 서버: 각 브라우저에서 수동 전송/잠시 나가기·재개/버튼 중앙 정렬, 9종 추천 모양 유지, 실제 완료→결과 로딩 중앙 정렬 검사를 통과했다. 추가로 모양 메타데이터 없는 기존 기록의 종류만 표시하는 분기도 양 브라우저에서 통과했다.
- 수면 드래그·짧은 드래그 복귀·키보드 개폐·타이머·반복 실행/종료 회귀 4개(브라우저별 2개) 통과.
- 모바일 360×640 / 390×700 / 412×780 / 430×800 / 844×390의 전체 페이지를 양 브라우저에서 순회했다(각 137상태). 노치 규격은 키보드 높이 360px의 가입·채팅을 포함한다. 수정 과정의 WebKit 가입 시트 실패와 고친 뒤 재검증을 분리해 기록한다.
- WebKit 마이크 진단 초기 2회는 인식 동작 이전 Home 진입에서 Target crashed가 발생했다. 독립 실행 시 해당 검사 통과. 과거 기록 테스트의 최초 실패는 제목 전체가 아닌 단어를 exact 검색한 locator 오류였고 수정 후 양쪽 통과.
- 직접 캡처 검토: 수동 전송 전 입력창, 만두 추천 유지, 결과 로딩 중앙, 새 이야기 버튼, 가입 키보드 높이, 가로 로그인, 수면 손잡이.

산출물은 Git 제외 `E:/Ganzithon/tooling/integration-20261120/` 아래 `manual-review-chromium`, `manual-mobile-webkit`, `manual-mobile-final`, `manual-voice-chromium`, `manual-voice-webkit`, `manual-voice-recheck`, `manual-microphone-webkit-isolated`, `native-manual-final`, `mobile-fixed-chromium`, `sheet-debug`, `viewport-focus-final`이다. 초기 실패와 마지막 통과를 구분한다.
