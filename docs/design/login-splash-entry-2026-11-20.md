# 로그인·스플래시 진입과 수면 배경 — 2026-11-20

## 첫 접속

- 이 진입 계약은 기본 real 실행/배포에 적용한다. 명시적 `dev:mock`은 기존 예시 계정·재질 검수 작업대로 유지하며 실제 인증 동작의 검증 근거로 사용하지 않는다.
- 일반 첫 방문은 `/` → `/login` → 인증 성공 → 스플래시 → 메인이다. 인증 확인 전에 Home을 마운트하지 않는다.
- `AppEntry`가 앱 단위로 `useProfile`을 구독한다. 미로그인일 때 메인·수면·MY를 포함한 앱 화면을 보호한다. 도움 연결 `/help`는 로그인과 독립적으로 접근할 수 있다.
- 이미 로그인된 같은 탭의 새로고침은 토큰 갱신/프로필 확인 → 스플래시 → 원래 경로로 복구한다. 유효한 세션에 로그인 폼을 다시 표시하지 않는다. 기존 sessionStorage 정책은 유지하며 브라우저 종료 뒤까지 유지되는 자동 로그인 기능을 새로 추가하지 않았다.
- 로그인/회원가입 성공, 로그인 경유, 로그아웃 이동은 replace를 사용한다. 스플래시는 별도 URL이나 history 항목이 아니다. 로그인 화면의 메인 우회 버튼은 제거했다. 로그아웃 뒤 브라우저 뒤로가기로 보호 화면에 접근하면 다시 로그인을 요구한다.
- 직접 `/archive`, `/sleep`, `/records/:id` 등에 들어온 경우 안전한 내부 next 경로를 보존한다. 일반 첫 방문은 메인으로 이동한다. 외부 URL/프로토콜 상대 URL은 로그인 후 이동 대상으로 허용하지 않는다.
- 인증 네트워크 오류는 재시도 화면으로 표시하고 미로그인으로 단정해 세션을 지우지 않는다. refresh가 거부된 만료 세션은 기존 정책대로 로그인으로 이동한다.
- 공개 도움말에서는 `useProfile(false)`로 인증 조회를 시작하지 않는다. 문서 단위 뒤로가기에서 도움말이 불필요하게 refresh를 회전시키고, 바로 앞으로 갈 때 응답 저장 전에 중단되어 세션이 풀리는 경우를 막는다. 같은 앱 안의 도움말 왕복에서는 기존 프로필/준비 상태를 유지한다.

## 스플래시

- 제공 ‘스플래쉬.png’의 흰 배경·중앙 양·동동체 ‘로딩 중…’을 실제 HTML/CSS로 구성한다. 시스템 시계·배터리는 복제하지 않는다. 양은 기존 제공 sheep-squishy.png를 재사용한다.
- 양은 2.6초 주기로 최대 4px/2.5%의 호흡 동작, 점은 1.4초 주기로 순차 이동한다. 모션 감소 환경에서는 정지한다. 메인 진입은 0.3초 페이드다.
- 사용자별 첫 준비에서 이미지 decode와 동동체 로딩을 기다린다. 최소 표시 시간은 0.7초, 자산 대기는 최대 3초다. 이후 일반 내부 이동/대화 이어하기에는 다시 재생하지 않는다. 실제 API 진행률이 없는 퍼센트는 표시하지 않는다.
- 계정 변경/로그아웃/언마운트 때 이전 준비 작업의 완료 처리를 무시한다. 기존 대화 상태나 API를 새로 생성·초기화하지 않는다.

## 수면 배경

- 제공 실행 화면 이미지의 상·중·하단 픽셀을 읽어, 기존 중간 색 #1D1C1B의 갈색 기운을 줄이고 #09090A → #17181A → #202125 → #27282C의 세로 그라데이션으로 조정했다.
- 양 주변 빛은 따뜻한 노랑에서 옅은 중성 회색으로 줄였다. 작은 중심광을 더하되 화면 전체를 밝히는 덮개를 넣지 않는다. 타이머·음원·기존 실행/종료 전환은 유지한다.
- 이번 비교 근거는 제공된 Figma 캡처다. Figma 파일에서 그라데이션 각도/정지점 수치를 직접 조회한 결과로 표현하지 않는다.

검증 결과는 docs/qa.md를 따른다. 백엔드 변경·PR·배포 없이 로컬 검토 단계다.
